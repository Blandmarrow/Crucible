# Export & bulk operations

This file covers bulk caption editing, bulk image rename/delete/count/reorder, detection-driven cropping, and the dataset export page.

### Bulk caption editing

`POST /captions/dataset/{dataset_id}/bulk-edit` (router: `backend/routers/captions.py`, service: `backend/services/caption_service.py::bulk_edit_captions`) — synchronous bulk text operation on caption_text across a dataset. Returns `{ affected, skipped }`.

**`BulkEditRequest`** fields:

| Field | Default | Effect |
|---|---|---|
| `operation` | required | `"prepend"` / `"append"` / `"remove"` / `"find_replace"` |
| `text` | required | Text to add (prepend/append) or text to find (remove/find_replace) |
| `replacement` | `""` | Replacement string for `find_replace` |
| `use_regex` | `false` | Treat `text` (and `replacement`) as a regex, compiled via `compile_user_regex` (the `regex` package — never stdlib `re`); an invalid pattern skips the whole batch. Matching is offloaded to a thread executor (real concurrency — `regex` releases the GIL) under a single 30-second time budget for the *entire batch*, enforced inside the engine via `regex_sub_deadline` (a `time.monotonic()` deadline, **not** `asyncio.wait_for`); returns 408 on timeout. See CLAUDE.md § Key invariants for why stdlib `re` + `wait_for` cannot bound a catastrophic pattern. |
| `image_ids` | `null` | If set, restrict to these image IDs |
| `quality_flags` | `null` | If set, additionally **exclude** images where any of these flags is `True` (AND IS NOT TRUE per flag); validated against `ALLOWED_FLAG_KEYS` from `utils.py` |
| `subfolder` | `null` | If set, restrict to images in this subfolder (ignored when `image_ids` is provided) |

Images with no `caption_text` are skipped for `remove` and `find_replace`. For `prepend`/`append` they receive just the added text. A single `db.commit()` is made after the loop — not per image.

**AI-artifact flag clearing.** Every caption-write site in `bulk_edit_captions` and `find_replace_captions` (both the plain and regex branches) calls `_maybe_clear_ai_artifact(img, new_text)` before writing the sidecar, so a bulk `remove`/`find_replace` that empties a caption also unmarks `has_ai_artifacts` — matching the single-image editor. See `docs/dev/captioning.md` § Captioning job execution (Flag lifecycle) for the helper. The `bulk-edit` and `find-replace` router endpoints (`routers/captions.py`) call `refresh_stats(db, dataset_id)` after the service returns so the Statistics page's AI-artifact count recomputes in the same request.

Per-caption subsumption cleanup (drop `tail` when `long tail` is present) is **not** a bulk-edit operation — it lives on the Consolidate Tags page as "Quick cleanup" (`POST /tag-consolidation/dataset/{id}/subsume`); see `docs/dev/tag-consolidation.md`. `BulkEditForm` invalidates the per-image `["caption"]` / `["image"]` query families on success (in addition to `["images", datasetId]` + the four stats keys) so an open `ImageDetailPage` refreshes immediately.

### Bulk image operations (rename / delete / count / provenance)

Four endpoints in `backend/routers/images.py` share a common `_apply_bulk_filters(query, image_ids, subfolder, quality_flags, include_flagged=False)` helper (module-level private function) that applies the triple filter — `image_ids` takes precedence over `subfolder`; `quality_flags` direction is controlled by `include_flagged`: when `False` (default) it excludes images where ANY flag is `True` (`AND IS NOT TRUE` per flag); when `True` it targets images where ANY flag is `True` (`OR IS TRUE` per flag). All of them accept a `BulkFilterBase`-derived schema (`backend/schemas/image.py`).

`BulkFilterBase` fields (shared by every one of these schemas): `dataset_id`, `image_ids: list[str] | None`, `quality_flags: list[str] | None`, `subfolder: str | None`.

| Endpoint | Extra fields | Returns |
|---|---|---|
| `POST /images/bulk-count` | `include_flagged: bool = False` | `{ count: int }` — count of matching images without making any changes |
| `POST /images/bulk-rename` | `new_stem: str`, `sort_by_sort_order: bool = False` | `{ affected: int }` — renames matching images to `{slug}_001.ext`, `_002`, … Uses `slugify_filename` + `unique_filename_with_thumb`; pre-plans all renames before touching the filesystem; DB updated via ORM bulk-by-PK executemany (includes `thumbnail_path`) then `rename_with_sidecar` + thumbnail `replace()` per file; sets `is_auto_named=True`. When `sort_by_sort_order=True`, images are ordered by `sort_order ASC NULLS LAST, created_at ASC` before numbering — used by the gallery's "Renumber Files" button. |
| `POST /images/bulk-delete` | `include_flagged: bool = True` | `{ deleted: int }` — permanently deletes matching images; calls `mark_image_deleted_in_versions` per image for versioning hooks; unlinks image, `.txt` sidecar, and thumbnail; calls `refresh_stats` |
| `POST /images/bulk-provenance` | `source_name` / `source_url` / `license` / `attribution`, each `str \| None`; `include_flagged` | `{ updated: int }` — sets source/license across the selection: an omitted field is left unchanged, `""` clears it to inherit the dataset default, anything else is written. Applied in chunked `sa_update` batches (`utils.chunked`, SQLite's 999-variable limit). `include_flagged` comes from the body like `bulk_count`/`bulk_delete` and defaults to **`False`**, matching `BulkCountRequest` and `bulk_rename`, so `quality_flags` selects the same set they would — it used to be hardcoded to `True`, i.e. the opposite set, and then defaulted to `True` while every caller passed it explicitly. An explicit `image_ids` selection can span datasets, so the query is scoped by `dataset_id` **only** for whole-dataset/subfolder selections, and `ensure_not_busy` runs for every dataset the rows actually touch. This is how an existing library of thousands of images gets labeled. Shares `_provenance_values()` with `PATCH /images/{id}/provenance` — see `docs/dev/gallery-and-images.md` § Source & license provenance. |
| `PATCH /images/batch/reorder` | `{ dataset_id, updates: [{id, sort_order}] }` | `{ updated: int }` — bulk-sets `sort_order` on a list of images; validates all IDs belong to `dataset_id` before updating. Used by drag-and-drop reordering in the gallery. |

**Frontend surfaces**:
- `SelectionToolbar` — **Edit** button (pencil icon) opens a modal with `<BulkEditForm imageIds={selectedIds} />`. On success, invalidates `["images", datasetId]` + all four stats queries and clears the selection.
- `BulkEditPage` (`/datasets/:datasetId/bulk-edit`, sidebar "Bulk Edit") — seven tabs: *Edit Captions*, *Upscale*, *Crop to Subject*, *Detections*, *Apply LUT*, *Rename*, and *Delete*. All tabs share the same scope radio (*All images* / *[Exclude/Only] images with quality flags* / *Currently selected*) and a **Subfolder** filter dropdown (shown when subfolders exist; hidden for the "Currently selected" scope). The quality-flag scope label and semantics depend on the active tab: on the Delete tab the label reads "Only images with quality flags" and `include_flagged=True` (OR logic — target images with any selected flag); on all other tabs it reads "Exclude images with quality flags" and `include_flagged=False` (AND NOT logic — skip images with any selected flag). `const targetsFlaggedImages = tab === "delete"` is the single source of truth for this distinction and drives the label ternaries, the `bulk-count` query fn, and the `bulk-count` query key (boolean, not the raw tab string — collapses the four non-delete tabs into one cache slot). A `POST /images/bulk-count` query fires on every scope/flag/subfolder/tab change and shows "N images will be affected" at the bottom of the scope panel. The flags scope requires at least one flag to be chosen before the form can submit. `qualityFlags` is passed to all five tab forms including `<UpscaleForm>` and `<LutForm>`.

`BulkEditForm` (`frontend/src/components/caption/BulkEditForm.tsx`) — reusable form. `qualityFlags` prop: uses those flags and hides the internal selector; when omitted the internal selector is shown. `disabled` prop prevents submission (used by `BulkEditPage` when scope is "flags" but nothing is selected).

**Detections tab** — renders two stacked panels: a **Run Detection** panel (`DetectionRunForm`) above a **Delete Detections** panel (`DetectionBulkDeleteForm`). Both take the standard bulk-form scope props (`datasetId, imageIds?, subfolder?, qualityFlags?, disabled?`) and share the page's "N images will be affected" counter (no per-form dry-run count on the run side).

- `DetectionRunForm` (`frontend/src/components/detection/DetectionRunForm.tsx`) — inline (non-modal) counterpart of the `SelectionToolbar` Detect modal; runs `POST /detection/run` across the scope. Model select (Florence-2 Large/PromptGen, NudeNet + min-confidence slider, SAM 2.1 text-prompt only — points are per-image and unavailable here, SAM 3), Florence task select (`<OD>` / `<CAPTION_TO_PHRASE_GROUNDING>`), use-caption-as-prompt checkbox, comma-separable prompt input, overwrite + watermark-sync checkboxes (sync gated on sam2/sam3/grounding, same `detectSyncEligible` rule), optional job label. Uses `detectionModelFamily` to reset task/prompt only on family change. Job tracking uses the **id-list pattern** (`jobIds: string[]`, see `docs/dev/frontend-core.md`) so multiple runs can be queued; toasts "Detection queued" at start and "Detection complete"/failure per job, invalidating detection queries + `["image"]` + `["images", datasetId]` on completion (the gallery key matters for watermark-sync runs, which change flag badges; TopBar's detection branch deliberately skips it).
- `DetectionBulkDeleteForm` (`frontend/src/components/detection/DetectionBulkDeleteForm.tsx`) deletes detections (not images) matching the shared scope plus optional label chips (`["detection-labels", datasetId]`), model chips (`["detection-models", datasetId]`), and a "Score below" number (0–1; unscored/manual rows never match). A **dry-run count query** — `bulkDelete({dry_run:true})` keyed on the full param set, `staleTime ~5s` (the POST is idempotent) — drives a live "N detections will be deleted" line; the real delete is gated behind a danger `ConfirmDialog` showing the count, and on success invalidates `["detection-labels"|"detection-models", ds]`, the count query, and `["image"]` (detail pages refresh without navigation).

This tab behaves like Crop/Upscale for scope (`targetsFlaggedImages` stays `tab === "delete"`, so it uses the exclude-flags semantics), not like the image Delete tab.

`DetectionJobRequest` (`backend/schemas/detection.py`) accepts `subfolder` + `quality_flags` (exclude images with these flags) for whole-dataset runs, applied in `run_detection`'s image query exactly like `bulk-delete`/`crop` — the same `normalize_subfolder` + `ALLOWED_FLAG_KEYS`-validated `as_boolean().is_not(True)` filters. Explicit `image_ids` win and bypass both filters.

`BulkRenameForm` (`frontend/src/components/image/BulkRenameForm.tsx`) — base-name input with live slug preview (`{slug}_001.ext, …`); `useMutation` → `imagesApi.bulkRename`; on success invalidates `["images", datasetId]`.

`BulkDeleteForm` (`frontend/src/components/image/BulkDeleteForm.tsx`) — amber warning panel + danger button; `useMutation` → `imagesApi.bulkDelete`; on success invalidates `["images", datasetId]` + all four stats queries and calls `selectionStore.clear()`.

### Detection-driven cropping (crop to detected subject)

`POST /detection/crop` (`backend/routers/detection.py::crop_to_detection`, schema `DetectionCropRequest`) — batch-crops images to their detection bboxes as a `crop_to_detection` BackgroundJob. Structured as a close mirror of `upscaling.py`'s `_run` (same scope triple, replace/new-file branches, progress-before-item, per-item failure continue, single commit, cancel handling).

- **Scope**: `image_ids` > `dataset_id` + `subfolder` + `quality_flags` (flag exclusion, `ALLOWED_FLAG_KEYS`-validated). `labels: list[str] | None` filters which detection labels drive the crop (None/[] = all); `label` (singular) is the job-label override — do not confuse the two.
- **Crop rect math** is the pure helper `backend/ml/mask_utils.py::detection_crop_rect(bboxes, img_w, img_h, mode, padding_pct, target_ar) -> (x, y, w, h) | None` (unit-tested in `backend/tests/test_detection_crop_rect.py`): sanitizes normalized bboxes, selects `mode="union"` (envelope of all matches) or `"largest"` (max area), pads each side by `padding_pct`% of the box's own extent, then optionally **grow-only** snaps to `target_ar` (never shrinks below the subject; clamps to the image; if no legal rect of that ratio contains the subject, the exact ratio is sacrificed rather than cutting the subject). Denormalizes against the DB `Image.width/height` — consistent because detection predictors open through `backend/ml/image_utils.py::open_rgb` (EXIF-transpose) and `crop_image_to_dest` opens through `image_service._open_safe` (also EXIF-transpose), so both work in the same transposed frame.
- Detections are prefetched with the chunked pattern (`_fetch_bboxes_by_image`, ≤10k ids per `IN`); images with no matching detections are counted request-side and returned as `skipped` in `{job_id, total, skipped}` (`total_items` counts only matched images, keeping the progress denominator honest).
- Per image: `None` rect → `skipped_no_detection`; full-image rect → `skipped_noop` (a no-op crop would only re-encode the file). **Replace** mode calls `protect_file_before_overwrite` then crops via `crop_image_to_dest` to a `{stem}_croptmp{suffix}` temp + `Path.replace()`, regenerates the thumbnail, updates `width/height/file_size_bytes/format/phash/updated_at` and appends a `crop_to_detection` entry to `processing_history` (list-concat reassignment). **New-file** mode derives `{stem}_crop` via `slugify_filename` + `unique_filename_with_thumb` and creates a new Image row. The new row's `subfolder` comes from the optional `dest_subfolder` field (`None` = inherit the source's subfolder — the default/backward-compatible behavior; `""` = root; any other string = that subfolder). `dest_subfolder` is `normalize_subfolder`-validated request-side (a `..` path 400s before the job starts) and ignored when `replace=True`. It is a logical label only — files still live flat in `{dataset}/images/`, so no filesystem move happens; the subfolder appears in listings automatically once the first cropped row exists (`dataset_service.list_subfolders` merges image-derived subfolders).
- Final counts land in `BackgroundJob.result_data` (`{cropped, skipped_no_detection, skipped_noop, failed}`); the terminal SSE message is always "Done.", so the frontend fetches the job on completion and toasts from `result_data`.

**Remapping detections through replace-mode crops.** Any crop that *replaces* the image changes its geometry, so its normalized detection coordinates must be re-expressed relative to the crop. `backend/ml/mask_utils.py::remap_detection_geometry(mask_json, bbox, rect, old_size)` is the pure remap: `rect` is `(x, y, w, h)` **in pixels of the OLD image's EXIF-transposed frame** (the frame detection coords live in — captured *before* `Image.width/height` are overwritten), `old_size` is `(old_w, old_h)` of that frame. Each coordinate maps `new = clamp((n*old_dim − offset)/extent, 0, 1)`. The bbox is the primary (non-nullable) geometry: if its remapped extent < 0.002 on either axis the detection is outside the crop and the fn returns `None` (delete the row). Polygon vertices are remapped+clamped (edge polygons flatten against the border — accepted); a remapped polygon with shoelace area < 1e-4 is dropped, and a masked detection that loses every polygon keeps its bbox with `mask=None`. The async orchestrator `backend/services/detection_service.py::remap_detections_for_crop(session, image_id, rect, old_size) -> (remapped, dropped)` selects all of an image's detections, deletes the `None` results and writes `det.mask` **then** `det.bbox` via ORM assignment (bbox last so the final `mask_area` listener recompute sees both — see `docs/dev/ml-models.md`). It does **not** commit; the caller owns the transaction. **Call sites** (each captures `old_size` before mutating dimensions): the `crop_to_detection` worker replace branch, `routers/images.py::crop` sync-replace path, `_run_crop_upscale_replace` (remapped only after a successful upscale — a failed upscale must not remap), and `routers/images.py::batch_crop` (`crop_to_aspect` returns its rect + orig dims for this single caller). **Exempt** (normalized coords are invariant under pure scaling): resize/`batch_resize` and all upscaling; new-file crop paths (the new row has no detections to remap). Coordinates are invariant under scale because they are already fractions of the image. Known limitation: a version-restore that swaps in an older image file does not remap detections (pre-existing, out of scope).

**Frontend**: `CropToDetectionForm` (`frontend/src/components/crop/CropToDetectionForm.tsx`) — shared form with the `UpscaleForm` props contract plus `disabled`; label chips from `["detection-labels", datasetId]`, mode radio, padding %, aspect `<select>` fed by `frontend/src/constants/aspectRatios.ts::ASPECT_PRESETS` (also consumed by the ImageDetailPage crop tool), New file/Replace radio, and a **Destination subfolder** `<select>` shown only in New-file mode (Same as source / root / existing subfolders from `["subfolders", datasetId]` / New subfolder… free-text, mirroring the `MoveToDatasetModal` sentinel pattern; resolved into the optional `dest_subfolder` payload field, and the completion effect also invalidates `["subfolders", datasetId]`). Surfaced as the **Crop** modal in `SelectionToolbar`, the **Crop to Subject** tab on `BulkEditPage`, and the **Crop to Subject** button in the `ImageDetailPage` toolbar beside Crop/Upscale/LUT (rendered only when the image has detections and crop mode is off; scoped to `imageIds=[imageId]`; passes the optional `availableLabels: {label, count}[]` prop so the chips show only that image's labels with per-detection counts instead of running the dataset-wide query, and its `onSuccess` additionally invalidates `["image", imageId]`). Job type `crop_to_detection` is registered in `TopBar`'s `IMAGE_MODIFYING_JOB_TYPES`.

### Export page

`ExportPage.tsx` supports 3 format buttons: kohya, ai-toolkit, plain folder. All three are fully implemented. The left panel uses `.form-row` layout throughout.

**Shared export loop**: `export_service.py` uses a shared `_run_export_loop(...)` helper that handles the DB query (column-explicit select, no blob fields), filter loop, progress emission, and result accumulation. It takes flat parameters — the source `db`/`dataset_id`/`image_ids`, the destination `dest_dir`, format/quality/resize settings (`output_format`, `jpeg_quality`, `resize_to`), the exclusion filters (`aesthetic_min`, `captioned_only`, `exclude_flags`, `style_sim_min`), job/progress identifiers (`job_id`, `job_type`), and caption/output flags (`caption_format`, `accumulate_plain`, `subfolders`, `strip_metadata`, `captions_only`) — and returns `{exported, jsonl_entries}`. There is no per-format callback: each of `export_kohya`, `export_aitoolkit`, and `export_plain` just calls it with their own destination directory and settings. Blob columns (`clip_embedding`, `dino_embedding`, `dino_layer_embeddings`) are excluded from the query — only `id`, `file_path`, `filename`, `caption_text`, `aesthetic_score`, `quality_flags`, and `style_similarity_score` are loaded. **Export order** is always `sort_order ASC NULLS LAST, created_at ASC` — datasets with a custom drag order export in that sequence; datasets without one export in stable chronological order. This determines the order of `captions.jsonl` entries and the on-disk write order; it does **not** rename files — exports keep each image's original stem (`_dest_img_path`). Numbered filenames (`0001.jpg`, …) only exist if the user ran the gallery's "Renumber Files" (bulk-rename with `sort_by_sort_order: true`) beforehand — see `docs/dev/gallery-and-images.md` § Manual image ordering.

**Per-run stem uniquification**: two source images can share a stem (e.g. `same.png` and `same.jpg`, or the `png`/`jpeg` output-format conversion collapsing extensions), which would make them clobber each other's exported image, caption sidecar, and mask. `_run_export_loop` tracks a `used_stems` set and rewrites `dest_img` through `_unique_stem(stem, used)` (module-level: `_001`, `_002`, … on collision) in **both** the captions-only and image branches. Everything downstream — the mask path, caption sidecar, and jsonl `file`/manifest entries — derives from `dest_img`, so they stay a consistent triple with no further changes. `_unique_stem` is deliberately **not** `utils.unique_filename`: that also probes the filesystem, which would rename every file on a re-export into the same directory; the collision guard is per-run only.

**Filters** (applied in `export_service.py::_is_excluded()`, shared by all three formats):

| Control | Param sent | Backend behaviour |
|---|---|---|
| Aesthetic ≥ N | `aesthetic_min: float` | Excludes images where `aesthetic_score` is NULL or below threshold |
| Has caption | `captioned_only: bool` | Excludes images with no `caption_text` |
| Per-flag checkboxes (one per `FLAG_OPTIONS` entry — Blurry / Noisy / Near-uniform / Watermarked / Duplicate / NSFW / AI artifacts) | `exclude_flags: str` (comma-separated flag names, e.g. `"is_blurry,has_watermark"`) | Excludes images where any of the named keys in `quality_flags` JSON is truthy |
| Style similarity ≥ N | `style_sim_min: float` | Excludes images where `style_similarity_score` is NULL or below threshold |
| Commercial-use only | `commercial_only: bool` | Excludes images whose effective license is not *known* to permit commercial use — `licenses.allows_commercial` treats `None` (unknown) as no |
| Specific licenses | `license_filter: list[str] \| None` | Keeps only images whose effective license is in the list; `""` is a meaningful entry (no license recorded). An empty list normalizes to None ("no filter"), never "match nothing" |
| Exclude unlicensed images | `exclude_unlicensed: bool` | Drops images whose effective license is `""`. **Deliberately its own flag, not `license_filter` set to every known id** — that allowlist would also drop every `other:<free text>` license, which *is* a recorded license. Was exactly that bug once |
| Exclude no-derivatives | `exclude_no_derivatives: bool` | Drops images whose effective license has `LicenseInfo.no_derivatives` (CC BY-ND) — an export ships resized/cropped copies, which ND forbids redistributing. Unlike `commercial_only` this is **not** conservative about unknowns: only a *known* ND license is dropped, so an `other:` free-text license is kept |

`exclude_flags` is parsed by `_parse_flags()` in `routers/export.py`, which validates every name against `ALLOWED_FLAG_KEYS` and raises HTTP 400 on an unknown key (captioning validates the same set via a pydantic `field_validator`, so it answers 422 instead — the check is equivalent, the status differs). **Call `_parse_flags` in the request path, never inside the job coroutine**: the three POST handlers enqueue a job and return `{job_id}` before the coroutine runs, so an exception raised in there fails the job instead of reaching the client. Each handler parses once into a local and closes over it.

Filter params are debounced 350 ms on the frontend; the preview query (`GET /export/preview/{dataset_id}`) reacts to changes and returns `{ image_count, will_export, captioned_count, excluded_low_aesthetic, excluded_uncaptioned, excluded_flagged, excluded_style_sim, excluded_license, unlicensed_count, sample_files }` — the total is `image_count`, not `total` (`frontend/src/api/export.ts` is the matching type). There is deliberately **no** per-license breakdown here: Stats owns that view via its Licenses panel, and the field the preview used to return was never rendered. `unlicensed_count` stays because the Export page renders it as a warning, and it is counted over the whole dataset scope rather than just what will export — "you have unlicensed images" stays true whether or not the current filters happen to drop them. `unlicensed_will_export` is its companion: how many of those actually ship under **every** filter. The client cannot derive it — guessing from the three license flags alone claimed "they still export" whenever a caption or aesthetic filter had already dropped them. `images_without_detections` is present **only** when `export_masks` is set. `excluded_license` covers all four license filters.

`license_filter` is a **JSON-array string** in the preview GET, parsed by `utils.parse_license_filter_param`, for the same reason as the mask labels: an `other:<free text>` id may contain commas. `GET /images/` uses the same helper and the same wire encoding, but **not the same treatment of `""`**: here `""` is a meaningful entry (images with no license recorded), while `GET /images/` expresses unlicensed through its own `license_missing` param and 400s on an all-blank list rather than silently returning everything. Both agree an empty list (`[]`) means "no filter", never "match nothing". See `docs/dev/gallery-and-images.md` § Source & license provenance.

**`unlicensed_count` means two different things.** In the *preview* it is counted over the whole dataset scope, not just what will export — the warning ("you have unlicensed images") stays true regardless of whether the current filters happen to drop them, and `ExportPage` derives its own `unlicensedExcluded` from the active filters so the banner's second sentence doesn't claim those images export when they won't. In the finished export job's `result_data` (built in `_run_export_loop` from the accumulated credits rows, surfaced by all three format functions) it counts **exported images only**.

**Provenance manifests**: `_run_export_loop` accumulates one credits row per exported image (using `resolve_provenance(img, ds_defaults)` — the parent dataset is fetched **once** before the loop via `_dataset_defaults`), then `_write_credits(manifest_target, credits)` writes `CREDITS.md` + `licenses.csv` into `manifest_dir` (the `output_dir` root, so all three formats put them beside the concept folder, not inside it). Always written even when nothing carries a license: a missing attribution file reads as "no attribution needed", which is precisely the claim an unlabeled dataset cannot make. `CREDITS.md` groups by license then source, attribution-required licenses first. `_EXPORT_COLS` carries the four provenance strings and **no `dataset_id`** — it doesn't need one, because every row in a loop belongs to the `dataset_id` the loop was called with, and that dataset's defaults are already in hand from `_dataset_defaults`. See `docs/dev/gallery-and-images.md` § Source & license provenance.

**Every value in a manifest is untrusted** — scraper, sidecar and EXIF strings. `_md_inline` collapses all whitespace and control characters, escapes the markdown specials that change document structure (`` \ ` * _ [ ] < > # | ``) and bounds the length, so a newline in `attribution` cannot forge a `## <license>` section in a legal attribution document. `_md_link` renders a URL as a link only when `utils.safe_external_url` accepts its scheme; anything else becomes inert escaped text. `_csv_cell` prefixes `'` to cells starting `=`, `+`, `-`, `@`, `\t` or `\r` so a spreadsheet reads them as data — the `csv` module already handles quoting, this is only the leading character.

`CREDITS.md` headings also state every obligation the license carries (`— attribution required, share-alike, no derivatives`, from `LicenseInfo`), and disambiguate an `other:` free-text license so it cannot render a heading visually identical to a curated vocabulary entry.

**Manifest lifecycle**: the export loop is wrapped in `except BaseException` so **any** non-completion — `CancelledError`, a truncated image, ENOSPC, EACCES — still writes the manifests for the partial set before re-raising. Written synchronously (a cancelled task is not obliged to schedule another await) and inside its own `try/except Exception: pass`, so a manifest write that fails on the same full disk cannot mask the original exception. Scoping this to `CancelledError` alone was the original bug: every other failure left images on disk with no `CREDITS.md`, the exact state the feature exists to prevent. The partial file says so in its header ("did not finish" — it covers failures, not just cancels).

Writes go through a temp file + `os.replace`. `_manifest_dest` refuses to clobber a pre-existing manifest describing a *different* file set (identical content is a no-op; differing content lands on `CREDITS.2.md`, `CREDITS.3.md`, …) — exports routinely share an output directory, and the manifests live in its common parent. The one exception is **supersede**: `_supersedes_existing_manifest(manifest_dir, dest_dir)` parses the existing `licenses.csv` and returns True when every path in its `file` column is under this run's `dest_dir`, meaning this run describes the same subtree again and should own the canonical name. One decision, read from `licenses.csv`, applied to both files so the supersede state cannot differ between them; anything unreadable, malformed or empty returns False and the numbered chain applies. `_write_credits` returns the names it wrote, which reach `result_data["manifest_files"]` and the Export page's completion line — a supersede, a numbered alternate and an identical-content skip all produce something other than `CREDITS.md`/`licenses.csv`, so the client must not hardcode those two.

A **partial** run takes its own base names, `CREDITS.partial.md` / `licenses.partial.csv` (`_write_credits` picks them from its `partial` flag; `_manifest_dest` alternation then applies within that pair, so two interrupted runs give `CREDITS.partial.md` and `CREDITS.partial.2.md`). Partial runs never supersede. Without the separate name, an interrupted run claimed `CREDITS.md` with its "did not finish" banner and stranded the later *successful* run's manifest on `CREDITS.2.md`, permanently leaving the incomplete one as the file a redistributor opens.

Note the asymmetry between the two files on a *non*-superseding re-export: `_render_credits_md` groups by license and source and names no files, so it is frequently byte-identical across runs and skipped as a no-op, while `licenses.csv` always differs (its `file` column). A `licenses.2.csv` with no `CREDITS.2.md` beside it is that case, not a bug — the existing `CREDITS.md` already describes the new run's credits.

The `file` column is **not** `_csv_cell`-guarded: it is a path this code generated, not scraped input, and the `'` prefix would corrupt a filename starting with `-`/`=`/`@`. The four provenance columns keep the guard. It is **relative to the manifest directory** (`_manifest_rel`), not a basename: images live one level down and a loss mask shares its image's basename. A captions-only run lists the caption sidecar it actually wrote, not the `.png` it never exported. `CREDITS.md` lists every distinct `source_url` in a source group rather than one representative — the primary ingest path records a site-level `source_name` with a per-post `source_url`, so collapsing them drops exactly the citable pages the attribution-required entries need.

**Caption format** (`caption_format: "txt" | "caption" | "jsonl"`): controls sidecar extension for kohya/ai-toolkit; `"jsonl"` writes a single `captions.jsonl` in the output root instead of per-image sidecars. Hidden for plain folder (always writes `captions.jsonl`). JSONL entries are `{file, caption}` — the old per-tag `tags.csv` and the `tags` key in each JSONL entry were dropped along with the tags table.

**Resize** (`resize_to: int | None`): after copying/converting, resizes the longest side to the given pixel count via Pillow (only downscales; originals untouched). Skips the PIL round-trip entirely when `resize_to=None`, `output_format="original"`, and `strip_metadata=False`.

**Strip metadata** (`strip_metadata: bool`, default `False`): when `True`, forces a PIL round-trip even for the "original format, no resize" case, which naturally discards PNG text chunks (A1111 `parameters`, ComfyUI `workflow`/`prompt`, etc.) and EXIF. The PIL paths (format conversion, resize) already strip metadata — this flag only affects the `shutil.copy2()` fast path.

**Loss-mask export** (`export_masks: bool`, default `False`; plus `mask_labels: list[str] | None` — None/empty = all labels, `mask_exclude_labels: list[str] | None` — regions always painted black, `mask_invert: bool`, `mask_missing: "white" | "skip"`): when enabled, each exported image gets a grayscale mask PNG for masked-loss training (kohya `conditioning_data_dir` / ai-toolkit `mask_path` — both match masks to images by filename stem, so mask stems always equal the exported image stems). Mechanics:

- Composition is `backend/ml/mask_utils.py::compose_loss_mask(include, exclude, w, h, invert)` (unit-tested in `backend/tests/test_mask_rasterize.py`): the base is `rasterize_detections(include, …, invert)` (full-white when `include` is empty, regardless of `invert` — an all-black mask would zero the image's loss), then excluded regions are punched black via `rasterize_detections(exclude, …)` (never inverted) pasted as 0 **after** the invert — so exclusion is subtracted after invert, and a label in both sets is black. `rasterize_detections(rows, w, h, invert)` itself is unchanged (also used by `polygons_to_mask_input`, where exclusion would be wrong): polygon JSON from `Detection.mask` scaled to the final exported dimensions and filled white via PIL `ImageDraw`; detections without polygons (Florence-2, NudeNet) fall back to filled bbox rectangles. `_write_image` returns the final `(w, h)` (post-EXIF-transpose, post-resize; the `shutil.copy2` fast path reads size + EXIF orientation tag without decoding pixels) so masks always match the exported image dimensions. It takes a `need_size: bool` param (caller passes `export_masks`): when masks are **off**, the fast-copy branch skips the PIL probe entirely and returns `None`, so a corrupt-but-copyable file still exports (size is only needed to rasterize a mask). The non-copy paths always compute the size because they must decode to save.
- Detections are **prefetched in one chunked query** (`_fetch_detections_by_image`, ≤10k ids per `IN`) before the loop — never per-image. It returns `(include_by_image, exclude_by_image)`; the WHERE filter is `label IN (mask_labels ∪ mask_exclude_labels)` when `mask_labels` is set (no label filter when None), and rows are split request-side with **exclude membership checked first** (exclusion wins).
- `mask_missing="white"` writes a full-white mask for images with no matching *include* detections (counted as `masks_full_white` — the fallback **path**; the written mask may still contain punch-outs from `mask_exclude_labels`); `"skip"` excludes them from the export entirely (`excluded_no_mask`). Exclude-only images (excluded labels but no include hit) count as "images without detections" and follow `mask_missing`. Result dict gains `masks_written` (+ `mask_dir` from the wrappers).
- Mask dirs: kohya `output_dir/{n_repeats}_{concept_token}_mask/`, ai-toolkit `output_dir/{concept_name}_mask/`, plain `output_dir/masks/`. Created only when masks are enabled; `captions_only=True` disables mask export.
- `mask_labels` / `mask_exclude_labels` are JSON lists in the POST bodies but **JSON-array strings** in the preview GET (`mask_labels=["a dog"]`), parsed by the shared `_parse_labels_json_param` — labels are free text and may contain commas, so no comma-splitting anywhere. The preview response gains `images_without_detections` when `export_masks=true`; its "with detections" set uses the *effective* include (`mask_labels` minus `mask_exclude_labels`; when every include label is also excluded the set is empty and no image counts as having detections; include None + excludes uses `label NOT IN exclude`), so preview and export agree that exclude-only images are without detections. The preview also accepts `mask_missing`, and with `skip` those images are excluded from `will_export`/`sample_files` so the headline count matches what the export will actually write.
- The ExportPage label chips (two groups: **Detection labels** to include, **Exclude from mask** to punch black) are fed by `GET /detection/labels/{dataset_id}` (`routers/detection.py`) → `[{label, image_count}]`, distinct labels joined against the dataset's images. The two groups share the same source and do not auto-deselect each other — the server's exclusion-wins rule handles any overlap.

**Captions only** (`captions_only: bool`, default `False`): when `True`, skips all image file writes. The `src.exists()` check is also bypassed so images with missing files are still included (their caption data is in the DB). For kohya/aitoolkit, only sidecar/JSONL caption files are written to the concept subdirectory. For plain, no `images/` subdirectory is created — only `captions.jsonl` is written to `output_dir`. In captions-only mode, JSONL entries always use `img.filename` (the original filename) regardless of `output_format`, since no format conversion occurs. Image format, resize, and strip-metadata settings are ignored when this flag is set.
