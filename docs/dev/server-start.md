# Server start: bind address & startup splash

This file covers what `manage.ps1` / `manage.sh` do to launch the server once the environment exists: how the bind address is resolved (`scripts/bind_host.py`, `--lan`, `CRUCIBLE_HOST`) and the `start`-only startup splash (`scripts/splash_server.py`) that holds :8000 until uvicorn answers. It mirrors the user doc `docs/server.md` (§ Starting up). Building the environment (venv, prerequisites, PyTorch wheels, SAM2/SAM3, the update flow) is in `docs/dev/environment-setup.md`; the request guard and server control endpoints are in `docs/dev/http-edge.md`.

## Bind address and `--lan`

The API has no authentication (GPT-007), so the launchers bind **loopback by default** and LAN access is opt-in. `scripts/bind_host.py` resolves the address — stdlib only, since it runs before any backend package is guaranteed — with this precedence: `--lan` (→ `0.0.0.0`) › `CRUCIBLE_HOST` in the environment › a `CRUCIBLE_HOST=` line in the repo-root `.env` (its own small parser: `export `, quotes, `#` comments; an empty value counts as unset) › `127.0.0.1`. `--urls PORT` prints the URL(s) another device can use, finding the outbound address with a UDP `connect` that sends no packet; it prints nothing for a loopback host. `--describe` is what the launchers actually call: three lines, the bind host, the *browse host* and `loopback` or `lan`. The browse host is `localhost` for a loopback or wildcard bind and the address itself otherwise, since a server bound to one LAN address does not answer on localhost. The launchers keep no loopback test or URL rule of their own; an earlier string-pattern copy in each shell disagreed with `is_loopback` (`0:0:0:0:0:0:0:1`, `localhost.`). They never read `.env` either, so this script is the one place the precedence lives; `Settings.crucible_host` exists only to keep the backend's unknown-`.env`-key warning quiet.

`start` and `dev` take the flag (`./manage.sh start --lan`; `.\manage.ps1 start -Lan`, with `--lan` also accepted) and pass the resolved host to every uvicorn invocation, including the restart loops and `dev`'s `--reload` one, and to the splash's `--host`. A non-loopback host also gets Vite's `--host` in `dev` — via `node node_modules/vite/bin/vite.js` in `manage.ps1`, because when `npm` resolves to `npm.ps1` PowerShell swallows the bare `--` of `npm run dev -- --host`. Loopback prints a one-line hint on how to opt in; anything else prints the LAN URL and a no-authentication warning. `manage.ps1` is deliberately a *simple* script (no `[Parameter()]`/`[CmdletBinding()]`) so an unrecognised `--lan` lands in `$args` instead of failing parameter binding; its variable is `$script:BindHost`, never `$host`, which is PowerShell's read-only automatic `$Host`. The browser the launcher opens, the printed URLs and `dev`'s Vite proxy all use the browse host. The proxy gets it through `CRUCIBLE_API_TARGET`, which `frontend/vite.config.ts` reads with a `http://localhost:8000` fallback. That is what lets `CRUCIBLE_HOST` name one interface address rather than `0.0.0.0`.

## Startup splash (`start` only)

`start` is silent for a long stretch before uvicorn answers: migrations, an occasional frontend rebuild, then the `backend.main` import chain. `scripts/splash_server.py` fills it — a stdlib-only `ThreadingHTTPServer` that binds the launcher's resolved host (`--host`, see § Bind address and `--lan`; it defaults to `127.0.0.1` like the launchers, and switches to `AF_INET6` for an IPv6 literal) on :8000 **before** `_migrate`, so the launcher can open a browser straight away on the app's real URL. It binds the **same address uvicorn does**, on purpose: a splash on `127.0.0.1` and an app on `0.0.0.0` look like two different listeners to anything forwarding the port (Docker publishing, a dev container, WSL), and the handover can then strand a browser that reached the splash through that forward. It answers `/api/v1/health` with **503**, `/favicon.svg` with the brand mark as `image/svg+xml` when one was loaded, and every other path with `scripts/splash.html`; the page polls that endpoint and does `location.replace("/")` on the first 200. Only the real backend answers 200, so that response *is* the handover signal — and the poll is same-origin, which is why the splash holds :8000 rather than being opened as a `file://` page (the backend grants no cross-origin reads at all, since there is no CORS; see `docs/dev/http-edge.md` § Request guard. Browsers are also tightening cross-origin requests to localhost). Ordering is the invariant: `_stop_splash` / `Stop-Splash` must complete before uvicorn binds. `CRUCIBLE_NO_BROWSER=1` skips the splash and the browser both.

**A bound socket is not a serving one**, and the gap between the two is where this broke on Windows. `HTTPServer.server_bind` resolves the bind address with `socket.getfqdn()` purely to fill in a cosmetic `server_name`; on Windows that reverse lookup can stall for seconds against a DNS server that has nothing to say about `0.0.0.0`. The socket is already listening by then, so the browser's connection sat accepted-but-unanswered in the backlog — a tab spinning forever on a blank page, with no animation to explain it. `SplashServer` overrides `server_bind` to skip the lookup, and the launcher no longer guesses: `--ready-file` names a sentinel written from inside `serve_forever`'s poll loop (via `service_actions`, reached only once the loop runs), and the browser opens only after it appears. If it never does within 10s the launcher stops the splash and starts without one, rather than hand uvicorn a busy port. Both launchers clear the sentinel before starting and after stopping, so a stale one from a crash can never read as "ready".

Three things it must not do, each of which cost a real failure mode to get right:

- **Import anything from `backend/`** — that drags in the very import chain the splash exists to cover. Stdlib only, and it renders its page once at startup.
- **Outlive its launcher.** A hard kill (PowerShell 5.1 skips `finally` on Ctrl+C) would leave it holding :8000 and break the next launch, so it takes `--parent-pid` and polls the parent every 2s (POSIX `os.kill(pid, 0)`; Windows `OpenProcess` + `WaitForSingleObject` via `ctypes`), with a `--timeout` (default 1800s) as a second backstop. bash traps `EXIT` only — the splash is a background child in the same process group, so Ctrl+C already reaches it, and trapping `INT` would change what Ctrl+C does to the uvicorn restart loop.
- **Serve anything cacheable.** Every response carries `Cache-Control: no-store`; without it the browser can hold the splash against the app's own URLs and serve it back long after the handover.

If the port is already taken the server exits **3**, its output is redirected to `/dev/null`, and the launcher drops the splash and opens no browser — uvicorn's own "address already in use" is the error the user should see. The restart loop never re-runs the splash: an in-app restart is covered by the TopBar overlay (`docs/dev/http-edge.md` § Server control endpoints).

The page never transcribes the mark. `build_page()` substitutes the `@keyframes` blocks and `<svg>` of `docs/images/Crucible Logo Animated.html` into two placeholders in `splash.html` — a plain replace-all, so a placeholder name must not appear anywhere else in the template. `scripts/check_mark.py` renders the page and diffs the result against the export (see `docs/dev/styling.md`).
