# Source & license provenance

This file covers where an image's source, license and attribution come from, how they
are inherited from the dataset, captured at ingest, carried through derivatives and
cross-dataset moves, exposed by the API, and edited in the UI.

The vocabulary itself and the read/write helpers live in `backend/licenses.py` — see
CLAUDE.md (§ Shared utilities) for the one-line index of every function named here.
Export-side consumption (CREDITS.md, licenses.csv, the license filters) is in
`docs/dev/export-licensing.md`; the snapshot mirror is in `docs/dev/versioning.md`.

## Model & schema

`Dataset` carries four NOT NULL defaults (`source_name`, `source_url`, `license`, `attribution`; `""` = unset). `Image` carries the same four as **nullable** columns plus `source_meta` (JSON — scraper long tail, `deferred=True` like the embedding blobs, so every reader that loads `Image` **as an ORM entity** must `undefer` it or a lazy load raises `MissingGreenlet` on the async session; those readers are `get_image`, the provenance PATCH, `create_snapshot`, and the four derivative paths that call `copy_provenance`). The rule is about entity loads only: a `select(Image.source_meta, …)` column list already has the value, which is why `batch_copy_dataset` and `duplicate_dataset` name it in their column tuples and add no `undefer`, and `batch_move_dataset` deliberately omits the column altogether (a move keeps the row's own `source_meta`). `VersionImageState` mirrors all five (see `docs/dev/versioning.md`). A third model carries them too: `Video` has the same four nullable columns and deliberately **no** `source_meta`, since nothing captures scraper sidecars for a video — see `docs/dev/video.md` § The model.

There is deliberately **no index on `(dataset_id, license)`**: every license filter runs on the effective license, `COALESCE(NULLIF(images.license,''), datasets.license, '')`, which is not sargable against one, and `EXPLAIN QUERY PLAN` confirms SQLite never chose it. Migration `b5e8d2a7c9f4` drops the one the feature originally shipped with.

## Inheritance rule

A NULL/empty image field means *inherit the dataset default*, resolved at read time by `backend/licenses.py::resolve_provenance(img, ds)`. Editing a dataset default therefore retroactively changes every non-overridden image — intended, not a bug. `resolve_provenance` is duck-typed (works on ORM rows and `select(...)` row tuples) and must never import models, or it re-introduces an import cycle.

## Capture precedence

At ingest — the first source to supply a field wins, and anything still unset stays NULL:

1. request-supplied provenance — **folder import only** (`DatasetImportWithOptions` →
   `routers/datasets.py` → `import_images_from_folder(provenance=…)`). Direct upload
   (`POST /images/upload`, which takes only `dataset_id, subfolder, files`) and folder
   rescan have no request layer; they capture from the file alone.
2. scraper sidecar — `image_service.read_provenance_sidecar()`, which accepts both
   `{filename}.json` (`pic.png.json`, gallery-dl's default) and `{stem}.json`, in that
   order. Checking only one silently skips half the real scrape folders.
3. embedded attribution — `image_service.extract_embedded_provenance()`: EXIF Artist
   (315) / Copyright (33432) for JPEG/TIFF, plus the `Author`/`Artist`/`Copyright`/
   `Attribution` PNG tEXt chunks read from `img.info` (a PNG has no EXIF Artist tag at
   all, so an EXIF-only read captured nothing for the most common format here).

Which paths capture what: **folder import** gets all three layers; **rescan** gets
sidecar + embedded; **drag-and-drop upload** gets embedded only, because the browser
sends the image bytes and nothing else. Dragging a gallery-dl folder onto the gallery
therefore drops its sidecar provenance — use folder import for scrape folders.

`read_provenance_sidecar` accepts the `{filename}.json` layout unconditionally (the
name is unambiguous) but requires the `{stem}.json` layout to carry at least one
recognised provenance key, or a ComfyUI `workflow.json` beside `workflow.png`, a
project `metadata.json` beside `metadata.jpg`, or one `12345.json` claimed by both
`12345.png` and `12345.jpg` would be adopted as provenance. Sidecars over
`_SIDECAR_MAX_BYTES` (256 KB) are skipped rather than read into a DB column.

Both run inside `_capture_provenance` in the existing executor hop (`_ingest_file_sync` / `_register_file_sync` in `dataset_service.py`), never on the event loop. `extract_embedded_provenance` populates **only** `attribution` — a copyright string is not a license id, and inferring one would put unverified images in the commercial-use bucket. Sidecar `license` strings run through `normalize_license`, falling back to `other:<raw>` rather than being dropped. `_SIDECAR_KEYS["source_url"]` prefers `post_url`/`page_url` over `file_url`: a direct file URL is routinely a signed, rotating CDN blob that is dead by the time anyone reads CREDITS.md.

**Capture truncates; the API rejects.** `licenses.merge_provenance(*layers)` is the left-wins merge every ingest path funnels through, and it ends in `clamp_provenance`, so an over-long scraped value is cut to its column width instead of failing the import. Its `fields=` argument narrows the column set for a model that lacks `source_meta` — video ingest passes `PROVENANCE_FIELDS`. The edit endpoints do the opposite and 422 — an API client must never silently lose data. Getting this backwards is what made an image's provenance permanently unsaveable: an uncapped 500-char `rights` value stored a 506-char license, which then failed the response schema on every save.

## Derived-image rule

Crop, upscale, LUT, detection-crop and **video frame extraction** all copy the parent's provenance verbatim via `licenses.copy_provenance(...)` — a derivative of a CC-BY-SA image is still CC-BY-SA. Frame extraction is the fifth consumer and the only one whose parent is not an `Image`: it calls `copy_provenance(video)` once per run and splats the result onto every frame it writes, which makes it the rights-carrying path for the whole video feature (`docs/dev/video-extract.md`). A `Video` has no `source_meta`, so the `getattr` default correctly yields `None` and no `undefer` is possible or needed there. Raw (not resolved), because the derivative stays in the same dataset and should keep tracking that default. Each of the four *image* loaders must `undefer(Image.source_meta)` — and `copy_provenance` deep-copies that dict, so parent, derivative and every snapshot of either do not share one mutable JSON object. `lut.py` / `upscaling.py` apply the `undefer` **only on the non-replace branch**: the replace branch never calls `copy_provenance`, so undeferring there would load the full scraper payload for the whole batch and discard it.

## ComfyUI synthetic stamping

ComfyUI import reads the **plan's** `output_is_synthetic` flag (`_comfy_output_provenance(synthetic, plan_name)` in `routers/comfy.py`), not the dataset. Nothing at run time can tell a text2img plan from one derived from licensed source material, and one dataset holds both kinds — inferring it from the dataset's defaults (the earlier design) credited a real photographer for generated images on any labelled dataset.

`ComfyPlan.output_is_synthetic` (bool, `NOT NULL DEFAULT true`, migration `c3f7a9e1d4b6`) is the plan's own declaration that its output is self-created. True stamps **three** of the four fields, all concrete: `license="synthetic"`, `source_name="ComfyUI"` and `attribution='Generated by ComfyUI plan "<name>"'` (plain `"Generated by ComfyUI"` when the plan name is blank, clamped to `FIELD_MAX_LEN["attribution"]`) — concrete because a blank attribution reads as "inherit" (`resolve_provenance` treats `""` and NULL alike), which credited a real photographer for an AI image in `CREDITS.md`. False returns `{}` so all four fields inherit **together** — never a partial stamp, which would mix a "synthetic" license onto an inherited real credit and hide a CC-BY-NC source from the commercial-use filter. Documented residual: `source_url` is the fourth field and is **never** stamped, so it inherits under either setting — every candidate value would be invented, and there is no honest one to write; the helper's docstring shows the manifest that produces.

`source_meta` is written **whether or not** the plan is synthetic — it records origin, not rights. It comes from `_comfy_source_meta(plan_row, row, wf)` — built from `wf`, the graph actually submitted, not the plan template, and computed **once per row** next to `wf` (deep-copied per image so multi-output rows never share one JSON dict). It records plan/row identity plus the model; `_workflow_checkpoints` reads `ckpt_name` / `unet_name` / `model_name` so Flux/SD3 `UNETLoader` graphs record a model too. See `docs/dev/comfyui.md`.

## Cross-dataset copy/move

`batch_move_dataset` and `batch_copy_dataset` call `licenses.materialize_by_source(rows, source_datasets)` — inherited values are written out concretely against the *source* dataset, or the image silently re-inherits the destination's unrelated default. **Per row, against its own source**: a selection can span datasets (that is what the toolbar's `datasetBreakdown` badges exist to show), so both routers derive `source_dataset_ids = {row.dataset_id for row in rows}`, fetch all of them, and drive the busy guard, the materialization and the closing `refresh_stats` off that set — never off `rows[0]`. Materialized values are concrete, so resolving them all against one dataset writes an unrelated license in permanently. `duplicate_dataset` is the exception: it copies the four dataset defaults onto the new dataset, so raw `copy_provenance` keeps inheritance equivalent. That covers `Video`'s four provenance columns too — under `include_videos` a copied video carries `source_name`/`source_url`/`license`/`attribution` raw for exactly the same reason (`Video` has no `source_meta`).

Move and copy **differ deliberately on `source_meta`**: `batch_move_dataset` strips it from the materialized values (a move does not change where the image came from, and the row keeps its own `source_meta` untouched), while `batch_copy_dataset` carries it onto the new row (which has none of its own). Not an oversight — don't "fix" one to match the other.

## API surface

**Videos have a read side and deliberately no write side.** `VideoOut` carries the same four raw columns plus a resolved `provenance` dict built by `resolve_provenance(video, ds)` in `_to_out`, and `VideoDetailPage` renders it as a badge, source name, link and attribution. There is no video provenance PATCH, no video entry in `bulk-provenance`, and no video row in `licenses-in-use` or the Stats breakdown — those aggregate `Image` only. So a video's own values are set at folder-import time or inherited from the dataset default, and afterwards can only be changed by editing that default. Record it as a decision before someone "fixes" it: see `docs/dev/video-endpoints.md`.

`ImageOut` carries the four raw string columns **plus** a resolved `provenance` dict (`{...fields, source_meta, inherited: [field names]}`) so the UI can show "inherited from dataset" vs "overridden". `source_meta` is in `provenance` **only** — it is a scraper's raw payload (up to the 256 KB sidecar cap above) and this response is refetched on every arrow-key navigation, so carrying it twice doubled that for nothing. `ImageListItem.license` is the *effective* value for the gallery badge. `GET /images/` gains `license_filter` and `license_missing`, applied as `COALESCE(NULLIF(images.license,''), datasets.license, '')` over a join. `license_filter` is a **JSON array** of effective ids, parsed by `utils.parse_license_filter_param` — the same *wire encoding* as the export preview, because an `other:<free text>` id may contain commas and comma-splitting would silently match nothing (`StatsPage`'s Licenses panel links straight into this param). **Any** blank entry is a 400 here, not just an all-blank list: this endpoint expresses "no license recorded" through `license_missing`, and dropping a blank would silently narrow a mixed list (fewer images than asked for) or void the filter entirely (every image). That differs from the export filters, where `""` is a meaningful entry — check which endpoint you are on.

**The two endpoints treat `""` differently — this is the easiest thing here to get wrong.** For export filters, `""` is a meaningful entry meaning "images with no license recorded". `GET /images/` expresses unlicensed through its own separate `license_missing` boolean instead, and **rejects with 400 any list containing a blank entry** — `[""]`, `["  "]` and a mixed `["CC-BY-4.0", ""]` alike (the guard is `any(not v for v in parsed)`, not an all-blank check) — naming `license_missing` in the message. It used to strip the empty entries and, finding nothing left, apply no filter at all — so a client following the export convention silently got *every* image back. Both endpoints agree that an empty list (`[]`) means "no filter", never "match nothing".

`POST /images/bulk-provenance` and `PATCH /images/{id}/provenance` share `_provenance_values()`: an **omitted** field (JSON `null`) means "leave unchanged", `""` — **or any whitespace-only string**, since the router does `raw.strip() or None` — means "clear to NULL so the dataset default applies", anything else sets that value. There is **no sentinel string** — an earlier `"__inherit__"` was treated identically to `""` by the router, so it added nothing and a source name of literally `__inherit__` cleared itself. A `license` that normalizes to `""` (a bare `other:`) also clears. Dataset-level provenance uses the same two meanings via `_apply_provenance_defaults` in `routers/datasets.py`.

**All four** string fields are capped at their column widths (`licenses.FIELD_MAX_LEN`: `source_name` 255, `source_url` 1024, `license` 64, `attribution` 2000) so an over-long value 422s rather than being silently truncated on a non-SQLite backend. `attribution` is a TEXT column, so the schema cap is the only bound it has. `license` is checked by a `field_validator` (`licenses.normalize_license_input`), **not** a `max_length`: normalization prepends the 6-char `other:` prefix *after* a `max_length` check would already have passed.

Both write endpoints call `ensure_not_busy` — `restore_snapshot` writes provenance, so an unguarded save would race a running restore — and `bulk_provenance` guards **every** dataset a selection touches, not just `body.dataset_id`, because an explicit `image_ids` selection can span datasets. Its `include_flagged` comes from the body like `bulk_count`/`bulk_delete` and defaults to **`False`**, so `quality_flags` selects the same set `bulk_rename` would; the frontend never sends it (the gallery selection is always an explicit `image_ids` list), so the schema default is what applies. The PATCH response populates `detections` exactly as `get_image` does, so a client can seed its per-image cache from it.

There is no `GET /licenses/` endpoint: it had zero consumers, and the backend↔frontend vocabulary is kept in sync by `test_frontend_license_vocabulary_matches_backend`, which parses `frontend/src/constants/licenses.ts` and diffs the ids and labels against `LICENSES`. A test fails the build; an unread endpoint does not.

**`GET /datasets/{id}/licenses-in-use`** (`dataset_service.get_licenses_in_use`) is the exception, and not a vocabulary endpoint: it returns `[{license, count}]` for the dataset's distinct *effective* licenses, most-used first, over the same `COALESCE(NULLIF(images.license,''), <ds default>, '')` expression as the stats breakdown. It exists because an `other:<free text>` license is **data, not vocabulary** — the compiled-in list cannot contain it, so a picker can offer one only by asking. Two rules that look like details and are not:

- **The dataset's own default is always included**, exempt from the cap below and carrying its real count (`0` when no image resolves to it). Without that, a free-text license typed into the dataset defaults is unpickable everywhere until some image happens to carry it — which is the gap this closes.
- **The tail is dropped, not collapsed.** `LICENSES_IN_USE_LIMIT` (100) is looser than `LICENSE_BREAKDOWN_LIMIT` because these counts are never summed to a dataset total, and `LICENSE_BREAKDOWN_OTHER_KEY` is not a selectable license. The cap is applied **in Python, not as SQL `LIMIT`** — same as the breakdown: capping in SQL hides the tail from the default's own lookup, so a default ranking past the cap comes back advertising `count: 0` while real images carry it.

`test_licenses_in_use_offers_every_value_the_filter_accepts` round-trips every `other:` value through `GET /images/` and asserts the advertised count. Note the endpoint reports the `""` bucket (no license recorded) that `GET /images/`'s `license_filter` **rejects with a 400** — that endpoint expresses unlicensed through `license_missing` instead. Dropping `""` is `useCustomLicenses`'s job, not the endpoint's, so a consumer must go through the hook rather than forwarding the raw response.

## Frontend

- **`constants/licenses.ts`** mirrors the vocabulary (labels + badge colors) and also owns `isBlankLicense`, `isKnownLicenseValue` and `EMPTY_PROVENANCE` — non-component exports live there rather than in a component file, which would disable fast refresh for both.
- **`components/image/ProvenancePanel.tsx`** (modeled on `GenerationMetadata.tsx`) renders and edits it on `ImageDetailPage`.
- **`components/common/ProvenanceFields.tsx`** is shared by the dataset create/edit modals and `ImportFolderModal`. The **create** modal carries the same fields, minus `customLicenses` — there is no dataset yet to read in-use values from; `DatasetCreate` extends `ProvenanceDefaults`, so `POST /datasets/` writes them in the same commit as the row.
- **Blank-`other:` guard**: `ProvenancePanel` blocks **Save**, and `SetProvenanceModal` blocks **Apply**, on a blank `other:` (`isBlankLicense`). Picking "Other (free text)…" without typing sends a bare `other:`, which normalizes to `""` server-side and *clears* the license — clearing has its own explicit control ("Inherit from dataset" / the Inherit mode). `SetProvenanceModal` extends that guard to **all four** fields: any field switched to "Set" but left empty blocks Apply, because `""` would reach the backend as a clear. Apply is also disabled while every field is still on "Keep".
- **`components/gallery/SetProvenanceModal.tsx`** drives the keep/set/inherit bulk action. Its entry point is a `ScrollText` **"Set source/license"** button in `SelectionToolbar`, between "Move to" and "Move to Dataset"; the modal posts `POST /images/bulk-provenance` with the explicit `image_ids`, receives the toolbar's `datasetBreakdown` as `sourceInfo` so a cross-dataset selection says so before it writes, and on success calls `invalidateProvenanceScope` + `clear()` and toasts `Updated N images`. Its `ModeToggle` is declared at module scope — a component declared during render is a new type every render, so all four toggle groups would remount on each keystroke and drop keyboard focus to `<body>`.

`ProvenancePanel` seeds its draft when the editor **opens** and never re-syncs from props while open; a sync effect would discard typed input on every background refetch. Editing is tracked by image id rather than a boolean so navigating to another image closes the editor instead of showing the previous image's draft — and `ImageDetailPage` additionally renders it as `<ProvenancePanel key={image.id} …>`, so the panel remounts on navigation. Keep both; the `key` is the part a reader editing that JSX will otherwise drop. The panel also owns the only UI anywhere that surfaces `Image.source_meta`: a **Scrape metadata** sub-collapsible rendering the raw key/value grid in a `max-h-48` scroll area, shown only when `provenance.source_meta` is non-empty. A `source_url` only becomes a link when `utils/url.ts::safeExternalUrl` accepts it (`http`/`https` only) — the value is scraped, and the same check exists backend-side as `utils.safe_external_url`.

**Free-text licenses are pickable, not just typeable.** `hooks/useCustomLicenses(datasetId)` wraps `GET /datasets/{id}/licenses-in-use` (query key `["licenses-in-use", datasetId]`, in `PROVENANCE_SCOPE`) and returns the `other:` values in use, dropping `""` and vocabulary ids because every caller renders those itself. `LicenseSelect` takes them as `customOptions` and renders a "Used in this dataset" optgroup: an in-use value selects its own option, anything else typed falls through to "Other (free text)…", and the free-text input stays visible either way so a picked value can still be edited — the whole widget remains stateless. Six call sites: `GalleryPage`'s filter and `ExportPage`'s "Specific licenses" list (which build their own option lists, not via `LicenseSelect`), plus `ProvenancePanel`, `SetProvenanceModal` (through `SelectionToolbar`) and `ProvenanceFields` from both `DatasetsPage`'s Edit modal and `ImportFolderModal`. The import dialog keys on its own selected **target**, not on the page's dataset, so the list follows the target selector; only the create-dataset modal omits it, having no dataset to read. Retyping was not a workable substitute: a one-character difference is a second, near-duplicate license bucket, and on the two *filters* the value was unreachable outright.

All three provenance writers call `constants/queryKeys.ts::invalidateProvenanceScope(qc)` rather than listing keys inline. The two **folder-import** completion handlers (`GalleryPage`, `DatasetsPage`) are the exception: they invalidate `["licenses-in-use", datasetId]` alongside their own dataset-scoped keys instead, because `PROVENANCE_SCOPE` is not scoped by dataset and would clear an unrelated pane's gallery. An import is still a provenance writer — a scraper sidecar is the largest single source of new `other:` licenses — so a handler that skips that key leaves them unpickable until the hook's 60 s `staleTime` lapses. Provenance resolves at read time, so one write changes the gallery badges, the Stats license breakdown *and* the Export preview's license counts — and split view means those are often mounted together. Editing a dataset's defaults from `DatasetsPage` is the widest case of all.

The `ImageCard` license badge lives in `uiPrefsStore` (`galleryLicenseBadge`), not in a localStorage read at render time, so toggling it in a Settings pane updates a gallery pane that is already mounted. Its Settings checkbox is deliberately **outside** the "Gallery defaults" group: that group's copy says its settings apply on first open and are cleared by the gallery reset button, neither of which is true of a global badge toggle. Off by default; when on it renders on **every** card, showing the muted "No license" descriptor for images with nothing set at either level — an image with no license is exactly what someone enabling the preference is looking for.

All three editors share **`components/common/LicenseSelect.tsx`** — the dropdown plus the **"Other (free text)…"** entry that is the only way to create an `other:<free text>` license. It is stateless: picking that entry stores the bare `other:` prefix, which is what reveals the text input, so an existing `other:<text>` value round-trips into the same option with no extra state. The free-text input's cap is computed, `maxLength={FIELD_MAX_LEN.license - OTHER_PREFIX.length}` — still 58, the `String(64)` column minus the 6-character prefix, but grepping for the literal finds nothing. Callers differ only in the empty option's label ("Not recorded" / "Inherit from dataset" / "— choose —"). Because a bare `other:` normalizes back to `""` server-side, `SetProvenanceModal`'s blank-set guard uses the exported `isBlankLicense()` rather than a plain truthiness check — otherwise a half-finished free-text entry would clear the license across the whole selection.

## Tests

`backend/tests/test_provenance.py` covers inheritance direction, snapshot restore, cross-dataset materialization, sidecar shapes, export manifests, the `license_filter` encoding, the length caps, and the `other:` semantics — plus `backend/tests/test_provenance_http.py`, which drives the same behaviour through the real routers over `httpx.ASGITransport` (see `backend/tests/conftest.py`). Router-shaped failures — the ComfyUI import crash, the uneditable over-long license — are invisible to service-level tests, which is why the harness exists.
