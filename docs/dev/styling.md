# Styling: the Tailwind/CSS design system, the brand mark & shared dialogs

This file covers the frontend's visual layer plus the shared dialog layer: CSS custom-property tokens, the reusable component classes in `@layer components`, the `CrucibleMark` brand mark and its export/drift constraints, `ConfirmDialog`, and the `useModalBehavior` hook every modal spreads. Component and state conventions live in `docs/dev/frontend-core.md`.

### Design tokens and component classes

Tailwind CSS v3 with a dark theme. Color tokens are CSS custom properties defined in `index.css` (`:root { --bg, --surface-1/2/3, --accent, --line, --fg, --warn, --bad, --info }`) and aliased in `tailwind.config.js` so they can be used as Tailwind classes. Geist/Geist Mono fonts are loaded via Google Fonts in `index.html`. Reusable component classes are defined in `frontend/src/index.css` under `@layer components`:

### The brand mark

**`CrucibleMark`** (`frontend/src/components/common/CrucibleMark.tsx`) — the brand mark: a 5×5 contact sheet that curates down to a C. Props: `size` (px, default 22), `animated`, `className`, `label`. Renders 25 rounded rects on a 64-unit viewBox; the `KEPT` set is the C, `BRIGHT` the four `--accent-2` cells, everything else the dropped grid at `--accent-dim`. Used at 22px in the Sidebar brand and 132px (animated) in the TopBar restart overlay. The **component** is token-driven — no hardcoded hex — so palette changes carry through automatically; both current callsites are decorative so the mark defaults to `aria-hidden`, and a callsite that stands alone should pass `label` to get `role="img"` + `aria-label`. The **app icon is not token-driven**: `frontend/public/favicon.svg` (a copy of `docs/images/crucible-icon.svg`) and the favicon/apple-touch PNGs hardcode the palette, because a standalone icon file is never in the document's CSS scope. On a palette change these must be re-exported by the designer and re-copied into `frontend/public/` — the CSS token change alone will not touch them.

The designer's exports are the source of truth for the geometry and live in `docs/images/` (`crucible-mark.svg` static, `crucible-icon.svg` the app-icon variant, `Crucible Logo Animated.html` animated, `icons/*.png` rasters, `README.txt` brand notes). **If you change the mark, change it there and in the component** — they are independent transcriptions of the same design and will silently diverge. `scripts/check_mark.py` diffs the component against the exports (cell roles, bright cells, per-cell animation variant, and the app-icon C shape) and byte-compares the `frontend/public/` favicons against their `docs/images/` sources, failing on any drift. It runs in CI (`.github/workflows/check-mark.yml`).

The launcher's startup splash is the one copy that is **not** a transcription: `scripts/splash_server.py` substitutes `Crucible Logo Animated.html`'s keyframes and `<svg>` into `scripts/splash.html` when it serves the page, so it cannot drift by construction. What can break is the substitution itself — a renamed export, a reworked `<style>` block, a placeholder edited out of the template — which fails silently as a splash with no mark on it, so `check_mark.py` renders the page through `build_page()` and diffs that. See `docs/dev/server-start.md` (§ Startup splash).

**Class names in `@layer components` must appear verbatim in the source.** Tailwind only emits a rule from `@layer components` if its selector is found as literal text when scanning `content` files, so a dynamically assembled class name (``className={`cm-keep-${variant}`}``) type-checks, renders, and is then **purged from the bundle** — the element carries a class that no CSS matches. This fails silently and only in a production build; the symptom is an element rendering unstyled with no error. Always write the full class name out (`variant === "a" ? "cm-keep-a" : "cm-keep-b"`), as `CrucibleMark` and `.pp-fill-indeterminate` do. `scripts/check_mark.py` asserts the built CSS still contains the mark's rules when `frontend/dist` is present.

`animated` attaches the `.cm-keep-a/b` and `.cm-drop-a/b` classes whose keyframes live in `index.css`. One 9.2s cycle: the grid flickers as if sampling, non-C cells shrink to dots and return, then vanish, leaving the C. The A/B split is a checkerboard (`(indexOf(x) + indexOf(y)) % 2`) so neighbouring cells fire on offset timelines. A `prefers-reduced-motion: reduce` block resolves the mark to its static form rather than freezing it mid-cycle.

**`--accent-dim` (`#0f6e4e`)** exists specifically for the mark's unresolved grid cells. It is *not* interchangeable with `--accent-deep` (`#064e3b`): at `--accent-deep` the dropped cells are dark enough that the C is already legible on frame one, which spoils the animation's reveal. Static cells use `--accent-dim` at `opacity .09` — the value the animation resolves to, and a near-exact match for `--accent-deep` once composited on `--bg`, which is why the static mark looks right either way and the difference only shows in motion.

### ConfirmDialog

**`ConfirmDialog`** (`frontend/src/components/common/ConfirmDialog.tsx`) — shared modal for destructive confirmations. It takes its dialog role, focus restore and Escape-closes behavior from `useModalBehavior` (§ Modal behavior below), passing `autoFocus: false` so the focus rules below stay authoritative, and never enabling backdrop-click close — a destructive confirm must be answered, not dismissed by a stray click. Escape maps to Cancel. Keyboard-aware: auto-focuses Cancel on mount by default (safe default for destructive actions), ArrowLeft/ArrowRight switch focus between Cancel and the confirm button, Enter fires the focused button natively. When adding any global `keydown` listener that handles ArrowLeft/ArrowRight, suppress it while a `ConfirmDialog` is open to avoid background navigation competing with dialog focus — see `showDeleteConfirm` guard in `ImageDetailPage`'s arrow-key effect. Accepts an optional `defaultFocus?: "cancel" | "confirm"` prop to override the focused button per-callsite. When `danger=true` and no `defaultFocus` is provided, the component reads `localStorage.getItem(CONFIRM_DEFAULT_KEY)` (from `constants/storage.ts` — see `docs/dev/persistence.md`) to respect the user's preference set in Settings → UI Behavior.

One sanctioned exception to the focus-Cancel rule: `DeleteBranchPrompt` (in `frontend/src/components/versioning/BranchSelector.tsx`) is destructive but keeps `useModalBehavior`'s default `autoFocus: true`, landing focus on its branch `<select>`. Choosing the branch *is* the dialog's task, and a `<select>` cannot be Enter'd into a deletion — the confirm button is a separate stop away. Do not "fix" this to match `ConfirmDialog`.

### Modal behavior

**`useModalBehavior`** (`frontend/src/hooks/useModalBehavior.ts`) — the single source of modal keyboard/ARIA behavior. Returns `{ overlayProps, panelProps }` to spread onto the overlay and the panel `<div>`; it adds no markup and no styles, which is why it is a hook first — the modals span Tailwind overlays, inline-styled panels and three z-index tiers. `ModalShell` (below) is the thin wrapper for the inline case. Options: `onClose`, `label` (accessible name), `closeOnBackdrop` (default off), `autoFocus` (default on). It gives the panel `role="dialog"`, `aria-modal`, `tabIndex={-1}`, restores focus to whatever opened the modal (unless that element is gone, as after a delete), and handles Escape and Tab/Shift+Tab cycling (focusables re-queried per keydown).

Four details are load-bearing. The handlers sit on the **panel**, not on `window`, so a stacked modal's Escape closes only the top one and the one underneath stays inert; Escape also calls `stopPropagation()`, which keeps a page's window-level Escape handler from firing behind an open dialog. The overlay's `onMouseDown` cancels the default focus change when the press lands on the backdrop — otherwise that click blurs the panel and Escape silently stops working. A panel handler cannot fire once focus is lost to `<body>`, which is what a focused control unmounting does (closing `DirPickerModal`'s inline new-folder row), so a narrow `document`-level Escape fallback covers it, gated on *nothing* being focused and on this panel being the last `[role="dialog"]` in the document — that gate is what keeps stacking correct. And the mount-focus target is resolved once into a ref: React applies `autoFocus` during commit, before effects run, so the hook moves focus only when nothing inside the panel has it, and the ref keeps StrictMode's dev-only remount from landing focus elsewhere.

Adopted by every extracted modal in `common/`, `gallery/`, `versioning/`, `comfy/` and `video/` (eighteen; `MoveSubfolderModal` could adopt it precisely because it shipped as its own component), plus `BranchSelector`'s two inline dialogs; elsewhere it is a spread on the existing divs, so never hand-roll Escape or focus handling again. Enable `closeOnBackdrop` only where that affordance already existed, never on a destructive confirm; give any nested control with its own Escape a `stopPropagation()` — `DirPickerModal`'s new-folder row, and `PromptPresetManager`'s save-name row, which sits inside the gallery's Caption dialog. `frontend/e2e/modal-a11y.spec.ts` covers Escape, stacking, focus restore and the backdrop rules.

**`ModalShell`** (`frontend/src/components/common/ModalShell.tsx`) is the answer for a dialog written inline in a long-lived parent. The hook has to mount with the dialog — called in a parent that stays mounted, it traps focus for as long as the parent lives — which used to mean extracting a component first, and is why those overlays stayed bare. `ModalShell` *is* that component: it calls the hook and renders the overlay and panel, so the inline JSX wraps in it and keeps all its state in the parent. Props are `label`, `onClose`, `closeOnBackdrop`, `overlayClassName`/`className`/`style`, `children`. It adds no visuals, so each call site passes its classes and keeps its z-index tier: the defaults are `.dialog-bg`/`.dialog` (z-index 60), and `SelectionToolbar` passes its `TOOLBAR_OVERLAY` (`z-50`, `ConfirmDialog`'s tier — the toolbar's `anyModalOpen` Delete-key guard keeps the two from stacking). `onClose` must do what the dialog's Cancel does: the Datasets page's dialogs (`components/datasets/`) discard the draft by unmounting, as Cancel does, and the toolbar's five job dialogs (upscale, LUT, crop, remove-WM, thumbnails) ignore Escape while their form reports a running job through `onRunningChange` — the same moment those forms disable Cancel, since closing unmounts the watcher that reports the result. Its users are the Datasets page's five dialogs in `components/datasets/` and `SelectionToolbar`'s ten (GPT-029), each named after its heading, with labels bound to inputs by `useId()` + `htmlFor`.

**Still bare** — a fixed overlay with no dialog role, no focus trap and either no Escape or a hand-rolled one. Each wants `ModalShell` (inline) or the hook (already its own component):

- `ImageDetailPage`: the Run Detection, Crop to Detection and Remove Watermark modals (inline).
- `GalleryPage`: the generation-metadata modal (inline; closes on backdrop).
- `FileBrowserPage`: `ImportModal`, `MkdirModal`, `DeleteConfirm` (already components).
- `StatsPage`: `SettingsDrawer`, `ImageLightbox`, `BucketPanel` (components, each with a hand-rolled `window` Escape).
- `ComfyDefaultsStrip`'s run-default editor and `ComfyRowsTable`'s bulk column edit (inline; close on backdrop). `ComfyPage`'s paste-prompts modal moved onto `ModalShell` in M6 §8d.

Not dialogs, and correctly without the hook: `TopBar`'s full-screen restart overlay, and `ImportFolderModal`'s transparent click-catcher behind its subfolder dropdown.

### Context menu

**`ContextMenu`** (`frontend/src/components/common/ContextMenu.tsx`) — a pointer-anchored menu, `position: fixed` at `(x, y)`. Props `{x, y, actions, onClose}`; an action is `{label, icon?, onClick, danger?, disabled?, title?}` and `icon` is optional, so a menu whose entries have no natural glyph renders without blank slots. A `disabled` entry is shown dimmed with `aria-disabled`, not the `disabled` attribute, because a disabled button shows no tooltip and `title` is where the reason goes. Six call sites: `FileBrowserPage`'s entry rows (`docs/dev/file-browser.md`), `GalleryPage`'s subfolder rows (`docs/dev/gallery/subfolders.md` § The subfolder row context menu), the ComfyUI page's plan rail and folder tree, which open it at a ⋯ button's corner as well as at the pointer (`docs/dev/comfyui/rows-tab.md`), and the library panel's category menu and the rows table's row menu (`docs/dev/comfyui/library-dnd.md`). Import it; never re-inline it.

It deliberately does **not** use `useModalBehavior`. That hook is modal-shaped — focus trap, `role="dialog"`, `aria-modal` — and a context menu is not a dialog. So Escape-to-close and outside-click-to-close live in this component instead, which is its answer to the never-hand-roll-Escape rule above: one implementation, not one per call site. Escape `stopPropagation()`s, so dismissing the menu does not also reach a page's own document-level Escape handler. A `useLayoutEffect` measures `getBoundingClientRect()` and clamps into the viewport (8 px pad) — required rather than cosmetic, since the gallery sidebar is 180 px at the left edge and a row near the bottom of a long tree would otherwise push the menu off-screen. The container carries `role="menu"` + `aria-orientation`, each button `role="menuitem"`. That button is the exported **`ContextMenuItem`** (`{action, onDone}`), and the panel's look is `MENU_PANEL_STYLE` in `frontend/src/components/common/menuStyle.ts` (its own module, since a component file exporting a constant trips `react-refresh/only-export-components`); `MenuButton` below renders its entries with both, so the two menus cannot drift apart.

**Keyboard** (M6 §8 review, 2026-11-05):
- **Focus and arrows.** The menu captures its opener (`document.activeElement`) on mount and focuses its first enabled item, or its first item when none is enabled. Arrow Up/Down wrap over **every** item, Home and End jump, and the keys it handles `stopPropagation()`.
- **A disabled item is focusable but inert**, the ARIA menu pattern (the user's ruling, 2026-11-07). It used to be skipped, so a menu whose items were all disabled, a ComfyUI folder's while its plan runs, had nothing to focus, its arrows were dead and no reason was reachable. Enter on a disabled item does nothing and leaves the menu open.
- **Handing focus back.** Escape and choosing an item hand focus back to the opener, skipping `<body>` and a detached element, so a right-click menu opened over the gallery hands back nothing. Focus is back on the opener before the dialog an item opens renders, so that dialog's `useModalBehavior` captures a live opener rather than the vanished menu item.
- **The opener toggles.** A `mousedown` on the opener while the menu is open closes it and swallows the click that follows, so pressing ⋯ again closes the menu rather than reopening it. Only an opener marked `aria-haspopup="menu"` toggles, which the four ComfyUI triggers (the rail's, the tree's and a category's ⋯, and a row's grip) carry: a right-click focuses whatever button it lands on, such as a gallery folder row's name, and that button's next click must still open the folder. It also works only where pressing a button focuses it (Chromium, Firefox on Windows), since the opener is whatever had focus.

Not implemented on purpose: portaling, submenus. The **lookalikes** anchored to a button rather than to a pointer are not this component and must not be converted to it by reflex — they share the behaviour, not the positioning, and that half lives in `usePopover` below.

### Anchored popovers

**`usePopover`** (`frontend/src/hooks/usePopover.ts`) — the non-modal sibling of `useModalBehavior`, for a panel anchored to a trigger button. Returns `{open, setOpen, anchorRef, triggerRef}`. `anchorRef` goes on the `position: relative` wrapper holding **both** the trigger and the panel, because outside-click is measured against it and a click inside the panel must not count as outside; `triggerRef` exists only so Escape can hand focus back rather than dropping it on `<body>`. Escape `stopPropagation()`s so it dismisses the panel and nothing else: `ImageDetailPage` (whose `LabelsPanel` renders a `LabelPicker`) carries a window-level Escape handler that cancels a detection draw, and a panel inside a `useModalBehavior` dialog would otherwise close the dialog too. `GalleryPage` has no Escape handler of its own. Four call sites: `GalleryPage`'s select-all caret menu, `LabelPicker`, `LabelsPanel`'s per-row colour swatch in Settings, and `MenuButton`. No roving focus, no portaling, no viewport clamping (unlike `ContextMenu`, which has roving focus and clamping).

**`MenuButton`** (`frontend/src/components/common/MenuButton.tsx`) — a button that opens a menu under it, for a short list of actions behind one trigger (M6 §8d's *Add ▾* on the ComfyUI Rows toolbar). Props `{label, actions, align?, className?, title?, testId?}`. `actions` are `ContextMenuAction`s, drawn by `ContextMenuItem`, so a disabled entry keeps its `title` tooltip; the plumbing is `usePopover`, and the trigger carries `aria-haspopup="menu"` and `aria-expanded`. **Choosing an entry refocuses the trigger before the entry's own dialog mounts**, so `useModalBehavior` records the trigger, not a menu item about to unmount, as the place to hand focus back when that dialog closes. An entry's `onClick` runs inside the click, so it may `.click()` a hidden file input. The panel floats absolutely, with the scroll-ancestor caveat `LabelPicker`'s `placement` states below; its one call site sits at the top of the ComfyUI page's scroller, where it has room. **`align` is a preference, not a rule**: on open the panel measures itself against its nearest scrolling ancestor and takes the other edge when the preferred one would be clipped, because a wrapping toolbar can carry a right-aligned trigger to the start of a new line. `GalleryPage`'s select-all caret menu predates it and could move onto it.

**`LabelPicker`** (`frontend/src/components/common/LabelPicker.tsx`) — two exports over the label vocabulary, and the answer to "one control per label does not scale". `LabelCheckList` is the body: a search box, a 240 px scrolling list, one native `<input type="checkbox">` per label with a colour dot and an optional count, and a `footer` slot the call site fills with its own semantics. `LabelPicker` wraps it in a `btn ghost sm` disclosure button (`triggerContent`/`triggerAriaLabel`/`active`). It knows nothing about filters or requests.

**`placement` is dictated by scroll ancestors, not by taste.** `"popover"` floats the panel absolutely and is correct only where nothing clips it — the gallery toolbar sets no `overflow`, which the select-all menu already proves. `"inline"` renders it in flow, and is required inside an `overflow-y: auto` container, where an absolute panel is cut off at the container's edge: the image detail rail and the Export page body are both such containers. The bulk modal skips the trigger and renders `LabelCheckList` directly, since the two lists *are* its content. Keyboard support is deliberately minimal — native checkboxes give Tab/Space and the focus ring, Escape closes and returns focus, and `Enter` in the search box is `preventDefault`ed. No arrow-key roving, for the reason above; a checkbox list is not a `listbox`, so plain form controls are the correct ARIA shape.

**The search box autofocuses in the `popover` placement only**, and `LabelPicker` derives that from `placement` rather than letting a call site pass it — the prop is `Omit`ted from `PickerProps` for exactly that reason. A popover opened on top of the page and dismissed with Escape may take the keyboard; an inline panel stays open across toggles, and `utils/keyboard.ts::isTextEntryTarget` reports **any** focused `INPUT` as text entry — so autofocusing one there silently disables the image detail page's arrows, Space, Delete and every label hotkey for as long as the panel is open. The same guard is why *clicking* a checkbox in the panel also parks the hotkeys until focus moves: narrowing it is not an option, since Space is bound to selection-toggle and would then both tick the box and toggle the image. `frontend/e2e/labels.spec.ts` asserts both halves — focused in the gallery popover, not focused inline, with the hotkey still round-tripping.

### CSS hist bars

The `.hist` class sets `display: grid; align-items: end; height: 90px`. For percentage `height` on bar children to resolve, you must also set `gridTemplateRows: "1fr"` as an inline style on the `.hist` div. Without this the single implicit row has no definite height and percentage heights collapse to 0.
