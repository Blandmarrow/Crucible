# Frontend core: state & shared components

This file covers the shared frontend conventions that are not tied to one page: TanStack Query and the Zustand stores, the `SelectionToolbar` action modals, the JS error console, and the shared numeric input `NumberField`. The `constants/` modules every page imports from are in `docs/dev/frontend-constants.md`. Five other neighbours split off it: background-job SSE and reporting are in `docs/dev/frontend-jobs.md`, job-completion cache invalidation in `docs/dev/job-invalidation.md`, the Sidebar/pane shell and route-level code splitting in `docs/dev/panes-routing.md`, storage keys and the persistent page state pattern in `docs/dev/persistence.md`, and the Tailwind/CSS design system, `ConfirmDialog` and the `useModalBehavior` hook every modal uses in `docs/dev/styling.md`.

## Frontend state

- **TanStack Query** — all server state (datasets, images, captions, jobs). Query keys follow `["resource", id]` pattern.
- **Zustand stores** — `selectionStore` (Set of selected image IDs + `datasetByImageId: Map<string, string>` tracking which dataset each selected image belongs to), `jobStore` (Map of active job progress from SSE — see `docs/dev/frontend-jobs.md`), `paneStore` (split-view pane layout — see `docs/dev/panes-routing.md` § Split view pane manager), `uploadStore` (active upload progress — see below), `errorConsoleStore` (captured JS errors — see below), `uiPrefsStore` (live UI preferences — see below). `selectionStore.toggle(id, datasetId)` and `selectionStore.selectAll(ids, datasetId)` both require a `datasetId` argument — all callsites (ImageCard, GalleryPage, ImageDetailPage) must pass it. `selectionStore.replaceRange(toAdd, toRemove, datasetId)` atomically removes `toRemove` IDs and adds `toAdd` IDs in one state update; used by GalleryPage shift-click range selection to replace the previous range with the new one without touching independently-selected images.
- **SelectionToolbar is `position: sticky`, not `fixed`.** It is the last child of `GalleryPage`'s scroll container, and `bottom-6 mx-auto w-fit` pins it 24 px above that container's bottom edge once there is enough content to scroll, while dropping it into the flow *below* the content when there is not. `fixed` covered whatever sat in the bottom ~90 px of the pane, which with a short grid is the pagination row: the bar floated over **Next →** and swallowed the click, a failure that only appears once the toolbar above is a row taller. Sticky also centres it on the pane rather than on the window, which is what split view wants. `frontend/e2e/gallery-select-all.spec.ts` is the regression test, since it pages a two-image grid with a selection live.
- **SelectionToolbar score modal**: the "Run Scoring" action accepts six boolean toggles — `run_technical`, `run_aesthetic`, `run_watermark` (CLIP zero-shot watermark detection), `run_embeddings` (CLIP embeddings), `run_dino` (DINOv2 embeddings), and `run_dino_layers` (DINOv2 per-layer — only shown/sent when `run_dino` is also checked). `run_watermark`, `run_embeddings`, `run_dino`, and `run_dino_layers` default to `false` since they add significant VRAM/time overhead. The modal also contains a collapsible **Style similarity** section (same controls as `QualityPage` — embedding model buttons, DINOv2 layer picker, `StyleReferencePicker`, Score similarity button) that calls `POST /quality/style-similarity` with `image_ids: ids` so similarity is scoped to the selected images only. Modal state that is session-specific (`showStyleSection`, `selectedRefIds`, `externalRefFiles`) is reset via `useEffect` when `showScore` becomes `false`; scoring preference toggles (`runAesthetic`, `runTechnical`, etc.) persist across open/close cycles.
- **SelectionToolbar caption modal**: the "Caption" action supports all four model types from the `["captioning-models"]` query (same payload as `CaptioningPage`): `local_models`, `ollama_models`, `wd14_models`, and `openai_compat_models`. A module-level `resolveModelId(base, providerModel)` helper assembles the full `openai_compat:{provider_id}:{model_name}` ID at mutation time. WD14 models show only a threshold slider (0–1, default 0.35) — the style picker, custom prompt, `PromptPresetManager`, and `ResolutionPicker` are hidden. OpenAI-compat providers render a `ModelPicker` inline below the selected provider row; `captionProviderModel` state tracks the sub-model. The query is gated on `enabled: showCaption` and the model section shows a loading message while `!modelsData`.
- **SelectionToolbar dataset breakdown**: because selections persist across dataset navigation, the toolbar pill and every action modal header show badge chips for each dataset represented in the current selection — solid style for the current dataset, amber `badge-warn` for images from other datasets. Computed via `useMemo` from `selectionStore.datasetByImageId` + the cached `["datasets"]` query (already fetched, `staleTime: 30_000`). `MoveToDatasetModal` receives this as `sourceInfo?: ReactNode`.
- **A SelectionToolbar action refreshes every dataset its selection spans, not just the pane it was fired from.** The selection crosses split-view panes, and several backends act on any dataset's ids, so invalidating the toolbar's own `datasetId` left the other pane showing rows that had been deleted or moved away (GPT-028). `selectionDatasetIds` (a `useMemo` over `datasetByImageId`, plus the pane's own id) is handed to each such action **as mutation variables**, which fixes the list at submit time — `clear()` empties `datasetByImageId`, so a list read after it would hold this pane alone. Delete calls `invalidateDatasetContentScope` per dataset; move-to-dataset does the same for every source plus the target. Upscale, LUT, crop-to-detection and remove-watermark start jobs whose completion the form itself watches, so `UpscaleForm`/`LutForm`/`CropToDetectionForm`/`InpaintForm` take an optional `selectionDatasetIds` prop, capture it in `onMutate`, and refresh each dataset's content scope on completion; TopBar still refreshes the job's own `dataset_id`. Labels and provenance already invalidate their whole scope bare. **Deliberately not widened**: caption, score (and its style-similarity run), detect, bulk caption edit and merge tags — their backends filter by `dataset_id` and silently *skip* the other datasets' ids, so nothing outside this pane changes and there is nothing to refresh (the skip itself is a separate gap). Move to subfolder sends one request per dataset (`idsByDataset`), since `POST /images/batch/move-subfolder` refuses a mixed selection (see `docs/dev/image-files.md`), and refreshes each.
- **QualityPage subfolder scope**: `POST /quality/score` (`ScoreRequest`) accepts `subfolder: str | None`. When set and `image_ids` is absent, the backend filters `Image.subfolder == normalize_subfolder(subfolder)` so only images in that subfolder are scored. `QualityPage` exposes a subfolder `<select>` in the "Run quality analysis" panel header (shown only when subfolders exist, uses the shared `["subfolders", datasetId]` query). `image_ids` (SelectionToolbar path) takes precedence over `subfolder` when both are provided.
- **Upload progress** (`frontend/src/store/uploadStore.ts`): `uploadStore` holds `progress: { datasetId, done, total, errors, skipped } | null`. `errors` counts requests that threw; `skipped` counts files the server answered 201 for and declined to store (an unsupported type). They are separate for the same reason `UploadTally` in `utils/uploadToast.ts` keeps them apart — only `errors` turns the bar amber, and a declined file reads as `· N skipped` in `--fg-mute`, not as a failure. Both surfaces count **files**, not images — the `TopBar` pill says `Uploading files` over a `done / total files` count, and the `GalleryPage` bar matches: videos upload through the same path, and the image/video split is not known until the responses land, which is what the summary toast reports. `GalleryPage` uploads files one at a time via `imagesApi.uploadSingle()`, writing progress to this global store after each file. `TopBar` (always mounted) reads the store and renders a `progress-pill` so the indicator persists across navigation. `GalleryPage` additionally shows an inline progress bar below the toolbar, filtered to the current dataset (`globalUploadProgress?.datasetId === datasetId`). `handleDrop` checks `!uploading` before calling `handleUpload` to prevent a drag-drop from starting a second concurrent upload that would clobber the store. Per-file `invalidateQueries` uses `{ cancelRefetch: false }` to coalesce rapid invalidations without cancelling in-flight gallery fetches.
- **UI preferences** (`frontend/src/store/uiPrefsStore.ts`): `uiPrefsStore` holds preferences that are localStorage-backed *and* must reach already-mounted components. Currently two fields: `galleryCheckboxSize` (px, 14–32, default 18), consumed by `ImageCard` and written by `SettingsPage`'s Gallery tab slider (both render the shared `GalleryCheckbox` component — see `docs/dev/gallery/selection.md`), and `galleryLicenseBadge` (bool, default off — the per-card license badge, see `docs/dev/provenance-api.md`). **Use this store rather than a `useState` + `localStorage.setItem` pair for any preference a mounted component renders from** — split-view panes can show `SettingsPage` and `GalleryPage` simultaneously, so reading the key at render or mount time leaves the gallery stale until it remounts. Preferences that are only read once at page-init time (gallery defaults, captioning defaults) do *not* belong here; they stay plain `localStorage` reads. Keys still live in `constants/storage.ts` (see `docs/dev/persistence.md`); the store owns the read/write so no component touches `localStorage` for these.
- **Error console** (`frontend/src/store/errorConsoleStore.ts`): `errorConsoleStore` holds `errors: ErrorEntry[]` and `isOpen: boolean` (session-only, no persistence). `addError(entry)` appends an entry (stamped with `nanoid()` id and `new Date()` timestamp) and sets `isOpen: true`. `clearErrors()` empties the array. `close()` hides the overlay without clearing. `ErrorEntry` has `id, timestamp, type ('error'|'unhandledrejection'|'boundary'), message, source?, line?, col?, stack?`. Two exported helpers: `errorTypeLabel(type)` → `'error'|'rejection'|'render'`; `formatErrorsForCopy(errors)` → plain-text string for the clipboard. The store drives both the `ErrorConsole` overlay and the `LogsPage` Errors tab.
- **`ErrorConsole` overlay** (`frontend/src/components/common/ErrorConsole.tsx`): always mounted at the `App` root (renders after `<BrowserRouter>` context, before `<Toaster>`). Registers `window.addEventListener('error', …)` and `window.addEventListener('unhandledrejection', …)` in a `useEffect` on mount; cleanup removes both on unmount. Renders a fixed bottom panel (`position: fixed; bottom: 0; left: var(--sidebar-w); right: 0; height: 280; zIndex: 9000`) only when `isOpen && errors.length > 0`. Header shows error count, **Copy Errors** (`<CopyErrorsButton>`) and **Clear** buttons, and a **×** close button. Each entry shows timestamp, type badge, message, optional `source:line:col`, and a collapsible `<details>` stack trace. The `--sidebar-w` CSS variable (set as `"240px"` on the root grid div in `App.tsx`) is used so the overlay aligns with the content area without hardcoding the pixel value.
- **`FileDropGuard`** (`frontend/src/components/common/FileDropGuard.tsx`): mounted once at the `App` root beside `RouteSyncer`, so it covers pane mode too. Window `dragover` and `drop` listeners in the bubble phase `preventDefault` a desktop-file drag (`types` includes `"Files"`) that no drop zone handled (`!e.defaultPrevented`), and set `dropEffect` to `"none"`. Without it, a file released just outside a zone opened in the tab and left the app, losing unsaved drafts. Every zone (`GalleryPage`'s grid, `DatasetsPage`, `ComfyRowsTable`, `WorkflowPinPanel`, `ImageCard`'s `.txt` drop) calls `preventDefault` before the event reaches `window`, so the guard never takes a real drop; a drop onto an `input[type=file]` is left alone. A new drop zone must keep that rule.
- **`CopyErrorsButton`** (`frontend/src/components/common/CopyErrorsButton.tsx`): the **Copy Errors** button, shared by the `ErrorConsole` overlay and the `LogsPage` Errors tab — the two renderings of the same list, whose handlers were byte-identical and identically broken (a `.catch(() => {})` that caught nothing, because the missing-API TypeError is synchronous and precedes the promise). Copies through `utils/clipboard.ts::copyText`, which works on an insecure origin. Feedback is a transient 1500 ms label swap (*Copied* / *Copy failed*) and deliberately **not** a toast: this surface reports the app's own failures, and a toast about the error console is noise on top of what the user is already reading. That also makes it the one clipboard site with a fixture-free success signal, which `frontend/e2e/insecure-origin.spec.ts` asserts.
- **`NumberField`** (`frontend/src/components/common/NumberField.tsx`): the shared numeric input for any bounded field — `{ value, clamp, onCommit }`. It holds the raw string while you type and applies `clamp` on blur, committing live only when clamping would be the identity, so a field never rewrites the prefix still being typed (`2048` into a 64–8192 input used to arrive as `8192`). Reach for this instead of `onChange={(e) => setX(clamp(Number(e.target.value)))}` on any input with bounds. Its full contract — the unmount commit, the stale-draft drop, and why nothing commits when no draft exists — is in `docs/dev/video/extract-controls.md` § NumberField, where its ten call sites live.
- **`ErrorBoundary` integration**: `componentDidCatch` in `frontend/src/components/common/ErrorBoundary.tsx` calls `useErrorConsoleStore.getState().addError({ type: 'boundary', … })` (using `.getState()` — safe from class component lifecycle methods) with `error.stack` and `info.componentStack` joined so both are visible in the overlay.
