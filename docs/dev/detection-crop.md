# Detection-driven cropping (crop to detected subject)

This file covers `POST /detection/crop` and the `crop_to_detection` job it enqueues: the
request scope, the crop rect math, the replace and new-file branches, and
`CropToDetectionForm`. The job shares its loop shape (per-item failure counting, the PM-013
commit ordering, `thumbnails_stale`) with the bulk jobs in `docs/dev/bulk-image-jobs.md`,
which also owns the detection remap every replace-mode crop runs. The detector whose boxes
it consumes is `docs/dev/detection.md`; its sibling consumer, which paints detections out
rather than cropping to them, is `docs/dev/inpaint.md`. The user-facing side is
`docs/detection.md` § Crop to detected subject.

## The job

`POST /detection/crop` (`backend/routers/detection.py::crop_to_detection`, schema `DetectionCropRequest`) — batch-crops images to their detection bboxes as a `crop_to_detection` BackgroundJob. Structured as a close mirror of `upscaling.py`'s `_run` (same scope triple, replace/new-file branches, progress-before-item, per-item failure continue, cancel handling) — including, since 2026-07-31, the same PM-013 ordering: its replace branch used to run an un-`try`-wrapped `generate_thumbnail` after `tmp_path.replace(src_path)` with the loop's only `commit()` afterwards, so a raise rolled back the geometry, `processing_history` and detection remaps of every image already overwritten on disk. It now commits per image and regenerates the thumbnail in a post-commit `try` that counts `thumbnails_stale`. `backend/tests/test_detection_crop_replace_http.py` pins the shape, the epilogue and the blast radius.

- **Scope**: `image_ids` > `dataset_id` + `subfolder` + `quality_flags` (flag exclusion, `ALLOWED_FLAG_KEYS`-validated). `labels: list[str] | None` filters which detection labels drive the crop (None/[] = all); `label` (singular) is the job-label override — do not confuse the two.
- **Crop rect math** is the pure helper `backend/ml/mask_utils.py::detection_crop_rect(bboxes, img_w, img_h, mode, padding_pct, target_ar) -> (x, y, w, h) | None` (unit-tested in `backend/tests/test_detection_crop_rect.py`): sanitizes normalized bboxes, selects `mode="union"` (envelope of all matches) or `"largest"` (max area), pads each side by `padding_pct`% of the box's own extent, then optionally **grow-only** snaps to `target_ar` (never shrinks below the subject; clamps to the image; if no legal rect of that ratio contains the subject, the exact ratio is sacrificed rather than cutting the subject). Denormalizes against the DB `Image.width/height` — consistent because detection predictors open through `backend/ml/image_utils.py::open_rgb` (EXIF-transpose) and `crop_image_to_dest` opens through `image_service._open_safe` (also EXIF-transpose), so both work in the same transposed frame.
- Detections are prefetched with the chunked pattern (`_fetch_bboxes_by_image`, ≤10k ids per `IN`); images with no matching detections are counted request-side and returned as `skipped` in `{job_id, total, skipped}` (`total_items` counts only matched images, keeping the progress denominator honest).
- Per image: `None` rect → `skipped_no_detection`; full-image rect → `skipped_noop` (a no-op crop would only re-encode the file). **Replace** mode calls `protect_file_before_overwrite` then crops via `crop_image_to_dest` to a `temp_sibling` temp, updates `width/height/file_size_bytes/format/phash`, calls `record_in_place(img, "crop_to_detection", …)` for the history entry, the `updated_at` stamp and `scores_stale` (set only when the row already carries a score), remaps the detections in the same transaction (`docs/dev/bulk-image-jobs.md` § Remapping detections through replace-mode crops), flushes, swaps the temp over the original with `replace_retrying`, commits, and only then regenerates the thumbnail in the epilogue — the stage, flush, swap, commit order of `docs/dev/bulk-image-jobs.md` § Batch resize and aspect crop. A failed item rolls back, so from then on the loop re-reads each row with `populate_existing` and `undefer(Image.source_meta)` rather than touching the expired instances it loaded up front. After the job's final commit it refreshes the stats of every dataset it cropped in (both modes move `total_size_bytes`).
- **New-file** mode derives `{stem}_crop` via `slugify_filename` + `unique_filename_with_thumb` and creates a new Image row. It carries the per-thumbnail-directory `occupied_by_dir`/`planned_by_dir` dicts rather than one flat set, because a selection can span datasets and each has its own `thumbnails/` — a single set would false-share stems across them. `docs/dev/image-files.md` § Image file naming (the occupied-stem set) points at this worker as the shape to copy. The new row's `subfolder` comes from the optional `dest_subfolder` field (`None` = inherit the source's subfolder — the default/backward-compatible behavior; `""` = root; any other string = that subfolder). `dest_subfolder` is `normalize_subfolder`-validated request-side (a `..` path 400s before the job starts) and ignored when `replace=True`. It is a logical label only — files still live flat in `{dataset}/images/`, so no filesystem move happens; the subfolder appears in listings automatically once the first cropped row exists (`dataset_service.list_subfolders` merges image-derived subfolders). The new row also inherits the parent's provenance verbatim (`**copy_provenance(img)`), which is why the worker's image query carries `undefer(Image.source_meta)` — see `docs/dev/provenance.md` § Derived-image rule.
- Final counts land in `BackgroundJob.result_data` (`{cropped, skipped_no_detection, skipped_noop, failed}`); the terminal SSE message is always "Done.", so the frontend fetches the job on completion and toasts from `result_data`.

## Frontend

`CropToDetectionForm` (`frontend/src/components/crop/CropToDetectionForm.tsx`) — shared form with the `UpscaleForm` props contract plus `disabled`; label chips from `["detection-labels", datasetId]`, mode radio, padding %, aspect `<select>` fed by `frontend/src/constants/aspectRatios.ts::ASPECT_PRESETS` (also consumed by the ImageDetailPage crop tool), New file/Replace radio, and a **Destination subfolder** `<select>` shown only in New-file mode (Same as source / root / existing subfolders from `["subfolders", datasetId]` / New subfolder… free-text, mirroring the `MoveToDatasetModal` sentinel pattern; resolved into the optional `dest_subfolder` payload field, and the completion effect also invalidates `["subfolders", datasetId]`). Surfaced as the **Crop** modal in `SelectionToolbar`, the **Crop to Subject** tab on `BulkEditPage`, and the **Crop to Subject** button in the `ImageDetailPage` toolbar beside Crop/Upscale/LUT (rendered only when the image has detections and crop mode is off; scoped to `imageIds=[imageId]`; passes the optional `availableLabels: {label, count}[]` prop so the chips show only that image's labels with per-detection counts instead of running the dataset-wide query, and its `onSuccess` additionally invalidates `["image", imageId]`). Job type `crop_to_detection` is registered in `TopBar`'s `IMAGE_MODIFYING_JOB_TYPES`.
