# Menus and popovers: the context menu, anchored popovers & the label picker

This file covers the frontend's non-modal overlays: `ContextMenu` (a menu anchored to the pointer), and `usePopover`, `MenuButton` and `LabelPicker` (panels anchored to a trigger button), with the keyboard, focus and placement rules they share. Dialogs are the modal half of that layer: `ConfirmDialog`, `useModalBehavior` and `ModalShell` live in `docs/dev/styling.md` § Modal behavior.

### Context menu

**`ContextMenu`** (`frontend/src/components/common/ContextMenu.tsx`) — a pointer-anchored menu, `position: fixed` at `(x, y)`. Props `{x, y, actions, onClose}`; an action is `{label, icon?, onClick, danger?, disabled?, title?}` and `icon` is optional, so a menu whose entries have no natural glyph renders without blank slots. A `disabled` entry is shown dimmed with `aria-disabled`, not the `disabled` attribute, because a disabled button shows no tooltip and `title` is where the reason goes. Six call sites: `FileBrowserPage`'s entry rows (`docs/dev/file-browser.md`), `GalleryPage`'s subfolder rows (`docs/dev/gallery/subfolders.md` § The subfolder row context menu), the ComfyUI page's plan rail and folder tree, which open it at a ⋯ button's corner as well as at the pointer (`docs/dev/comfyui/rows-tab.md`), and the library panel's category menu and the rows table's row menu (`docs/dev/comfyui/library-dnd.md`). Import it; never re-inline it.

It deliberately does **not** use `useModalBehavior`. That hook is modal-shaped — focus trap, `role="dialog"`, `aria-modal` — and a context menu is not a dialog. So Escape-to-close and outside-click-to-close live in this component instead, which is its answer to the never-hand-roll-Escape rule in `docs/dev/styling.md` § Modal behavior: one implementation, not one per call site. Escape `stopPropagation()`s, so dismissing the menu does not also reach a page's own document-level Escape handler. A `useLayoutEffect` measures `getBoundingClientRect()` and clamps into the viewport (8 px pad) — required rather than cosmetic, since the gallery sidebar is 180 px at the left edge and a row near the bottom of a long tree would otherwise push the menu off-screen. The container carries `role="menu"` + `aria-orientation`, each button `role="menuitem"`. That button is the exported **`ContextMenuItem`** (`{action, onDone}`), and the panel's look is `MENU_PANEL_STYLE` in `frontend/src/components/common/menuStyle.ts` (its own module, since a component file exporting a constant trips `react-refresh/only-export-components`); `MenuButton` below renders its entries with both, so the two menus cannot drift apart.

**Keyboard** (M6 §8 review, 2026-11-05):
- **Focus and arrows.** The menu captures its opener (`document.activeElement`) on mount and focuses its first enabled item, or its first item when none is enabled. Arrow Up/Down wrap over **every** item, Home and End jump, and the keys it handles `stopPropagation()`.
- **A disabled item is focusable but inert**, the ARIA menu pattern (the user's ruling, 2026-11-07). It used to be skipped, so a menu whose items were all disabled, a ComfyUI folder's while its plan runs, had nothing to focus, its arrows were dead and no reason was reachable. Enter on a disabled item does nothing and leaves the menu open.
- **Handing focus back.** Escape and choosing an item hand focus back to the opener, skipping `<body>` and a detached element, so a right-click menu opened over the gallery hands back nothing. Focus is back on the opener before the dialog an item opens renders, so that dialog's `useModalBehavior` captures a live opener rather than the vanished menu item.
- **The opener toggles.** A `mousedown` on the opener while the menu is open closes it and swallows the click that follows, so pressing ⋯ again closes the menu rather than reopening it. Only an opener marked `aria-haspopup="menu"` toggles, which the four ComfyUI triggers (the rail's, the tree's and a category's ⋯, and a row's grip) carry: a right-click focuses whatever button it lands on, such as a gallery folder row's name, and that button's next click must still open the folder. It also works only where pressing a button focuses it (Chromium, Firefox on Windows), since the opener is whatever had focus.

Not implemented on purpose: portaling, submenus. The **lookalikes** anchored to a button rather than to a pointer are not this component and must not be converted to it by reflex — they share the behaviour, not the positioning, and that half lives in `usePopover` below.

### Anchored popovers

**`usePopover`** (`frontend/src/hooks/usePopover.ts`) — the non-modal sibling of `useModalBehavior`, for a panel anchored to a trigger button. Returns `{open, setOpen, anchorRef, triggerRef}`. `anchorRef` goes on the `position: relative` wrapper holding **both** the trigger and the panel, because outside-click is measured against it and a click inside the panel must not count as outside; `triggerRef` exists only so Escape can hand focus back rather than dropping it on `<body>`. Escape `stopPropagation()`s so it dismisses the panel and nothing else: `ImageDetailPage` (whose `LabelsPanel` renders a `LabelPicker`) carries a window-level Escape handler that cancels a detection draw, and a panel inside a `useModalBehavior` dialog would otherwise close the dialog too. `GalleryPage` has no Escape handler of its own. Four call sites: `GalleryPage`'s select-all caret menu, `LabelPicker`, `LabelsPanel`'s per-row colour swatch in Settings, and `MenuButton`. No roving focus, no portaling, no viewport clamping (unlike `ContextMenu`, which has roving focus and clamping).

**`MenuButton`** (`frontend/src/components/common/MenuButton.tsx`) — a button that opens a menu under it, for a short list of actions behind one trigger (M6 §8d's *Add ▾* on the ComfyUI Rows toolbar). Props `{label, actions, align?, className?, title?, testId?}`. `actions` are `ContextMenuAction`s, drawn by `ContextMenuItem`, so a disabled entry keeps its `title` tooltip; the plumbing is `usePopover`, and the trigger carries `aria-haspopup="menu"` and `aria-expanded`. **Choosing an entry refocuses the trigger before the entry's own dialog mounts**, so `useModalBehavior` records the trigger, not a menu item about to unmount, as the place to hand focus back when that dialog closes. An entry's `onClick` runs inside the click, so it may `.click()` a hidden file input. The panel floats absolutely, with the scroll-ancestor caveat `LabelPicker`'s `placement` states below; its one call site sits at the top of the ComfyUI page's scroller, where it has room. **`align` is a preference, not a rule**: on open the panel measures itself against its nearest scrolling ancestor and takes the other edge when the preferred one would be clipped, because a wrapping toolbar can carry a right-aligned trigger to the start of a new line. `GalleryPage`'s select-all caret menu predates it and could move onto it.

**`LabelPicker`** (`frontend/src/components/common/LabelPicker.tsx`) — two exports over the label vocabulary, and the answer to "one control per label does not scale". `LabelCheckList` is the body: a search box, a 240 px scrolling list, one native `<input type="checkbox">` per label with a colour dot and an optional count, and a `footer` slot the call site fills with its own semantics. `LabelPicker` wraps it in a `btn ghost sm` disclosure button (`triggerContent`/`triggerAriaLabel`/`active`). It knows nothing about filters or requests.

**`placement` is dictated by scroll ancestors, not by taste.** `"popover"` floats the panel absolutely and is correct only where nothing clips it — the gallery toolbar sets no `overflow`, which the select-all menu already proves. `"inline"` renders it in flow, and is required inside an `overflow-y: auto` container, where an absolute panel is cut off at the container's edge: the image detail rail and the Export page body are both such containers. The bulk modal skips the trigger and renders `LabelCheckList` directly, since the two lists *are* its content. Keyboard support is deliberately minimal — native checkboxes give Tab/Space and the focus ring, Escape closes and returns focus, and `Enter` in the search box is `preventDefault`ed. No arrow-key roving, for the reason above; a checkbox list is not a `listbox`, so plain form controls are the correct ARIA shape.

**The search box autofocuses in the `popover` placement only**, and `LabelPicker` derives that from `placement` rather than letting a call site pass it — the prop is `Omit`ted from `PickerProps` for exactly that reason. A popover opened on top of the page and dismissed with Escape may take the keyboard; an inline panel stays open across toggles, and `utils/keyboard.ts::isTextEntryTarget` reports **any** focused `INPUT` as text entry — so autofocusing one there silently disables the image detail page's arrows, Space, Delete and every label hotkey for as long as the panel is open. The same guard is why *clicking* a checkbox in the panel also parks the hotkeys until focus moves: narrowing it is not an option, since Space is bound to selection-toggle and would then both tick the box and toggle the image. `frontend/e2e/labels.spec.ts` asserts both halves — focused in the gallery popover, not focused inline, with the hotkey still round-tripping.
