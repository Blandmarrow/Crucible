# Quality scoring and flags

This file covers the per-image measurement half of quality: the quality scorers and the columns they write, the failure contract every scorer follows when it cannot measure, the flag thresholds and where they are configured, and what the frontend e2e suite reaches.

Three subjects that used to share this title now have their own files. `docs/dev/scores-stale.md` covers the `scores_stale` bit that qualifies every score documented here — one writer, one clear predicate, three rendered surfaces. The comparisons *between* images have two: `docs/dev/image-similarity.md` for pHash duplicate grouping, and `docs/dev/style-similarity.md` for the CLIP/DINOv2 style-similarity flow — including the `StyleSimilarityRun` descriptor and `GET /quality/style-similarity/{dataset_id}`, which exist because `style_similarity_score` is the one score column whose *scale* depends on which mode wrote it, so unlike everything documented here it cannot be read on its own.

The scorers are loaded and evicted through the shared model manager — see `docs/dev/ml-models.md`.

## The scorers and their columns

Quality scorers and what they add to `Image`:
| Module | Columns written | Notes |
|---|---|---|
| `ml/technical_scorer.py` | `blur_score`, `noise_score`, `uniformity_score`, `color_score`, `saturation_score`, `luminance_score`; flags `is_blurry`, `is_noisy`, `is_uniform` | Pure OpenCV/numpy, no GPU |
| `ml/aesthetic_scorer.py` | `aesthetic_score` (1–10), `aesthetic_model`, `watermark_score` (0–1), flag `has_watermark`, `clip_embedding` (BLOB, float16) | CLIP ViT-L-14; text encoder used for zero-shot watermark; image encoder for embeddings. Also owns the shared batch loop both aesthetic producers run through — see § The aesthetic model picker. |
| `ml/aesthetic_v2_5_scorer.py` | `aesthetic_score` (1–10), `aesthetic_model` | Aesthetic Predictor V2.5: SigLIP-so400m-patch14-384 plus a linear head, via the `aesthetic-predictor-v2-5` package. Per-image inference only; no loop of its own. |
| `ml/dino_scorer.py` | `dino_embedding` (BLOB, float16), `dino_layer_embeddings` (BLOB, float16) | `dino_embedding`: final-layer CLS token, 768-dim. `dino_layer_embeddings`: all 12 transformer-layer CLS tokens concatenated, 18 432 bytes (12 × 768 × float16); layer N (1-indexed) at offset `(N-1)*768*2`. `slice_layer_embedding(blob, layer)` extracts one layer's bytes — defined in `similarity_scorer` and re-exported here, so it stays reachable without torch. |
| `ml/nsfw_scorer.py` | `nsfw_score` (0–1, rounded to 4 dp); flag `is_nsfw` | `Marqo/nsfw-image-detection-384` ViT at 384 px, ~1.0 GB through `model_manager.load_nsfw`; threshold `nsfw_threshold` |
| `ml/similarity_scorer.py` | — | CPU-only and **numpy-only** (a structural test pins the second, so the quality router's combined branch imports on a torch-free runner). `compute_style_similarity(ref_bytes, cand_bytes)` — cosine similarity of candidates to mean reference. `compute_combined_similarity(...)` — weighted blend, delegating its arithmetic tail to `blend_scores`. Also home to `slice_layer_embedding` and the three constants that decide what a style run means: `STYLE_CLIP_WEIGHT` (0.30), `STYLE_DINO_WEIGHT` (0.70), `DEFAULT_DINO_LAYER` (9). See `docs/dev/style-similarity.md`. |

`luminance_score` was added by migration `c4b8e6a2f107` — no index, and no backfill is possible, since the value needs pixels. It is mean grayscale normalised to 0–1 (0 = black, 1 = white), taken from the `gray` array `score_technical_sync` already computes for blur/noise/uniformity — no extra decode. It has **no quality flag**, deliberately: a score with no flag needs no `threshold_settings` column, no Settings row and no `ALLOWED_FLAG_KEYS` entry, and `is_uniform` already flags a solid black frame. It **is** mirrored on `VersionImageState`, like every `*_score` column — `c4b8e6a2f107`'s own docstring says the opposite and is superseded by `d1c7b4e9f0a3`, which added the mirror later on the same branch: nothing recomputes a technical score without a manual quality job, so a snapshot is the only record of an old one (`test_every_score_column_is_mirrored_on_version_image_state` is the guard, and `NOT_MIRRORED` in `backend/tests/test_video_lineage_mirrors.py` holds no score). The score exists for **all** images, but the question it answers is a video-frame one: a triage pass dumps hundreds of frames into a subfolder and the usable-brightness ones have to be separable from night scenes, fades to black and blown-out flashes. See `docs/dev/video-extract.md`.

The column is NULL until the technical scorer runs again, and nothing detects that: `score_coverage["technical"]` counts `blur_score` alone, so a dataset scored before the column existed reports full technical coverage beside an empty Brightness histogram. Stats carries the re-score hint that says so — see `docs/dev/statistics.md` (`score_coverage`). The same staleness applies to `color_score`/`saturation_score` on anything last scored before quality-v2, and to whatever technical column is added next.

`backend/tests/test_luminance_score_http.py` pins the **wiring** rather than the formula, which is where a new score field actually breaks: that `luminance_score` is in `_ALLOWED_SCORE_FIELDS` for both filter forms (an omission is a 400), that it appears in the `score_filters` array form, that `dataset-stats` and `score-values` carry it, and that a NULL brightness is absent from both the histogram and the filter rather than counting as 0. The formula itself is deliberately untested — it lives in `score_technical_sync`, which imports cv2 — matching the coverage shape of every other technical score. (Not for want of cv2 in CI: both workflows install `opencv-python-headless` for the video suite, per `docs/dev/image-similarity.md` § Duplicate detection. The formula is untested because a numeric assertion on a mean-grayscale value pins arithmetic, not behaviour.)

## The failure contract

**The technical scorer's failure contract is "nothing measured", not zeros.** Both branches — `cv2.imread` returning None for an unreadable file, and an exception out of the executor in `score_images_technical` — return the shared `_unmeasured()` dict: all six scores `None`, all three flags `False`, one logged warning each. A zero is a *measurement*; writing 0.0 claimed the image was pitch black, perfectly uniform, fully desaturated and (via `is_blurry=True`) out of focus, about a file no decoder ever read. The booleans stay `False` rather than `None` because `routers/quality.py` folds them into a JSON flags dict via `t.get(..., False)`, where `None` is not expressible. Every consumer is already null-safe — nullable `Float` columns assigned straight through, histogram buckets guarded on `is not None`, `get_score_values` skipping `None`, nullable pydantic schemas and TypeScript types. The visible consequence is that such a file now reads as **unscored** rather than inflating `score_coverage["technical"]` and sitting in the darkest brightness bucket; `docs/scoring.md` says so for users.

**That contract is now the file's, not just the technical scorer's.** Aesthetic, watermark and NSFW wrote `0.0` on an exception out of the executor until 2026-07-31 — an aesthetic 0.0 being outside the column's own 1–10 range, and the watermark branch logging nothing at all — which is the same defect in three more columns. All three now write NULL with a logged warning, and their booleans stay `False` for the same reason the technical scorer's do. `backend/tests/test_scorer_failure_contract.py` holds that half.

`backend/tests/test_technical_scorer_failures.py` is what holds that contract: both failure branches (an unreadable file, a missing file, and an exception raised out of the executor) against a readable control, plus a structural check that the assertion list covers **every** field the scorer writes — so a seventh score column added without a null default fails there rather than in a histogram. Three of the five cases call `score_technical_sync` for real and carry `@needs_cv2`; the executor branch monkeypatches the scorer to raise before it imports anything, and the structural check only reads `_unmeasured()`, so those two need no decoder at all. All five run in CI, which installs cv2 — the marker is for a local venv without it.

## The aesthetic model picker

`aesthetic_score` has two producers: LAION's `sac+logos+ava1-l14-linearMSE` MLP over CLIP ViT-L/14 (marker `laion`) and Aesthetic Predictor V2.5 over SigLIP-so400m (marker `v2_5`). Which one runs is a **per-run choice with a sticky default**, not a setting: `aestheticModel` rides in the already-global `QUALITY_WORKFLOW_KEY` blob beside `embeddingType` and `dinoLayer`, and arrives as `ScoreRequest.aesthetic_model`. There is no DB setting and no per-dataset override — the control sits in the same panel as the button that runs it, which makes a cross-dataset carry-over *more* visible than a stored setting would. It is a `Literal["laion", "v2_5"]`, so an unknown value is a 422 rather than an unknown marker in the column, and `body.model_dump()` carries it onto `BackgroundJob.config` and into the job's auto-label (`"Quality: technical, aesthetic (V2.5) — 100 images"`) for free.

**The loop is shared, the per-image callable is not.** `score_images_batch(paths, handle, job_id=…, model=…)` picks between `score_image_sync` and `score_image_v2_5_sync` *above* its loop, importing the V2.5 module inside the branch so a LAION run never imports the package. Duplicating the loop would duplicate the SSE cadence, the `job_queue.cancel_requested` check and the None-on-failure contract above — three things this repo has already had to fix once each. `handle` is per-model on purpose: `aesthetic`'s `ModelEntry.model` is a three-tenant `{"clip", "mlp", "preprocess"}` dict, while `aesthetic_v2_5` returns the plain entry and the V2.5 scorer reads `.model` + `.processor`. See `docs/dev/ml-models.md` for why V2.5 gets its own registry entry rather than replacing the existing one.

### The marker is a safety device, not bookkeeping

`Image.aesthetic_model` records which model produced each stored score, because both scales land in 1–10 and that is **all** they share. Two consumers act destructively on the number: `aesthetic_min` in `export_service.py` omits images invisibly, and `rankForKeepBest` in duplicate resolution *deletes* them. So the guards ship with the capability that creates the hazard, not later — the moment a second model is selectable a dataset can hold two scales in one column.

The invariant every consumer leans on is

> `aesthetic_score IS NOT NULL` ⟺ `aesthetic_model IS NOT NULL`

established by migration `a5e1b7c3d9f0`, which backfills `'laion'` onto every existing scored row. The backfill is legitimate here and was not for `scores_stale` for one reason: the historical value is *knowable* — LAION was the only producer that had ever written the column. Without it, five consumers would each re-derive a three-way rule (scored-and-marked / scored-but-unknown / unscored). `routers/quality.py` maintains it at the single write site: the marker is assigned inside the same `i < len(aesthetic_scores)` guard as the score, and set back to NULL when the score is. A marker beside a NULL score would claim a model looked and produced nothing; a stale marker on an overwritten NULL would put a phantom row in the per-model breakdown.

`aesthetic_model` is deliberately **outside** `_JOB_SCORE_COLUMNS` and never enters the router's `refreshed` set — see `docs/dev/scores-stale.md`. It *is* mirrored on `VersionImageState` and diffed; see `docs/dev/versioning-service.md`. It is carried by all five field-by-field rebuild paths, enrolled in their structural guard by its own `info={"qualifies": "aesthetic_score"}` rather than by the `*_score` suffix those guards otherwise derive from (`backend/tests/test_video_lineage_mirrors.py`).

No Enum and no CHECK constraint: a future learned head writes `head:{uuid}` into this column, so the value set is open. Every frontend consumer therefore renders an unrecognised marker verbatim rather than swallowing it — `frontend/src/constants/aestheticModels.ts` is the one place the two known markers are named, shared by the picker, the duplicates refusal, the export advisory and the Stats breakdown.

### The two destructive consumers differ, on purpose

- **Duplicate resolution refuses.** `DupGroupMeta.mixedModels` is true when a group's scored members carry more than one marker; per-group *Keep best* is then disabled with a title naming the models found, and a small producer label renders under each thumbnail's score chip so the refusal explains itself outside a tooltip. `rankForKeepBest` itself stays untouched — it is a pure, null-safe sort and is correct *within* one scale; the refusal belongs at the caller, where the unscored refusal already lives. **The bulk bar skips mixed groups rather than disabling itself**, counted separately as `skippedMixed` beside `skipped` and stated in the confirm dialog: killing the whole bar because 1 of 300 groups is mixed pushes users to resolve by hand in the gallery. *Keep first* reads no score and is untouched.
- **Export warns.** `get_export_preview` emits `aesthetic_models` and `aesthetic_models_will_export`, both `{marker: count}` — the same whole-scope / will-export pair the stale-scores and unlicensed advisories use. Dicts rather than a bool, because the useful sentence is *"1,204 by LAION, 766 by V2.5"*: the skew is what says whether one `aesthetic_min` threshold is over- or under-including. Advisory only — it never blocks, never changes `will_export`, and adds no exclusion row. It renders whenever more than one marker is present rather than only when filtering, because the gallery's aesthetic sort reads the same column.

### Per-model coverage and the re-score offer

Two surfaces, two mechanisms, deliberately not shared:

- **Stats** gets a `GROUP BY Image.aesthetic_model` beside the existing three-count coverage query, emitted as flat `aesthetic_{marker}` keys in `score_coverage`. **`aesthetic_*` is a reserved prefix** in that dict. No schema change (it is `dict[str, int]`) and the CSV export picks them up for free. They are *not* added to `StatsPage`'s `coverageDefs`, which stays at four entries: that list is a fixed four-column grid and the producer set is open-ended. The page renders a breakdown line under the Aesthetic tile instead, and only when more than one producer is present.
- **The Score images page** gets its own endpoint, `GET /quality/aesthetic-coverage/{dataset_id}?subfolder=` → `{"scored", "unscored", "by_model"}`. It needs the page's subfolder scope and a refetch on job completion, and dragging `get_dataset_stats` onto a page that otherwise makes three light queries would be the expensive way round. `by_model` sums to `scored` — that is the arithmetic the backfill buys.

**The re-score offer takes a scoping flag, not an id round-trip.** `ScoreRequest.only_mismatched` adds `Image.aesthetic_score.isnot(None), Image.aesthetic_model.isnot(body.aesthetic_model)` to the selection query, so it composes with `subfolder` like every other scope and the selection stays atomic with the run. It deliberately excludes never-scored rows: plain *Run scoring* already covers those, and two buttons with two literal meanings beat one with a mode.

## Flag thresholds

Flag thresholds:
| Flag | Column | Default threshold | Source |
|---|---|---|---|
| `is_blurry` | `blur_score` (Laplacian variance) | < 100 | `blur_threshold` in `threshold_settings` DB table |
| `is_noisy` | `noise_score` (smooth-region std dev) | > 15 | `noise_threshold` in `threshold_settings` DB table |
| `is_uniform` | `uniformity_score` (grayscale std dev) | < 12 | `uniformity_threshold` in `threshold_settings` DB table |
| `has_watermark` | `watermark_score` (CLIP zero-shot, 0–1) | ≥ 0.6 | `watermark_threshold` in `threshold_settings` DB table |
| `is_duplicate` | `phash` (perceptual hash Hamming distance) | < 8 | `duplicate_threshold` in `threshold_settings` DB table |
| `is_nsfw` | `nsfw_score` (Marqo classifier, 0–1) | ≥ 0.5 | `nsfw_threshold` in `threshold_settings` DB table |

`gdino_threshold` (default 0.35) in `threshold_settings` controls the Grounding DINO box confidence cutoff passed to SAM2 `text_prompt` detection — read via `get_thresholds()` at the start of each SAM2 detection job. `text_threshold` scales with it (`gdino_threshold - 0.10`, floored at 0.01).

`sam3_threshold` (default 0.5) in `threshold_settings` is the SAM 3 instance confidence cutoff — read at the start of each SAM3 detection job and applied as `Sam3Processor.confidence_threshold` (plus a defensive per-instance filter in `predict_sync`).

All thresholds are user-configurable via Settings (`/settings` → `GET/PATCH /api/v1/settings/thresholds`). Quality flag thresholds take effect on the next scoring run; `gdino_threshold`/`sam3_threshold` take effect on the next SAM2/SAM3 detection run. Constants in `technical_scorer.py` serve only as parameter defaults — the quality router always passes DB-fetched values via `backend/services/threshold_service.py::get_thresholds()`.

## Frontend coverage

**Frontend coverage**: `frontend/e2e/quality.spec.ts` drives the GPU-free half of `QualityPage` in two specs. The first covers the three panels, the default scoring selection (aesthetic + technical on), the DINOv2-conditional per-layer row, the aesthetic model picker (defaults to LAION, survives a reload, returns to LAION on *Reset to defaults*), the subfolder scope select, and that the duplicates query resolves. The second covers the style-similarity prerequisite: it expands the panel (the coverage query is `enabled`-gated on that), picks *CLIP + DINOv2* — which also exercises the mode→layer effect — and asserts the layer select reads 9, the missing-embeddings warning is visible and *Score similarity* is disabled with the reason in its `title`. The e2e dataset has no embeddings, which makes that deterministic and is the cheapest end-to-end proof of `GET /quality/embedding-coverage` with no torch. Neither spec clicks *Run scoring*: the e2e workflow installs cv2 (it is the video ingest gate) but **not** torch, and the default selection includes aesthetic scoring, so that click would fail the job body rather than the page.

Two selectors in that spec were fixed alongside the picker. `scorer('Aesthetic score · LAION')` had to lose the model name, which is no longer in the checkbox's label; and the subfolder scope moved from `page.locator('select').first()` — which survived by DOM-order coincidence — to a filter on its `All subfolders` option, since the page now renders a second `<select>`. The picker's sub-row is deliberately **not** a `<label>`: `scorer()` matches labels by text, and a second one containing "Aesthetic" would make it ambiguous.

**Backend coverage**: `backend/tests/test_aesthetic_model_marker.py` holds the marker end to end and is torch-free — the structural placement (nullable on both tables, in the diff lists, out of both `*_score`-derived universes), the request contract (the marker reaches `BackgroundJob.config` and the label; an unknown value is 422), the duplicates payload carrying it on a flagged member *and* the prepended root, the export preview pair tracking the filters, `only_mismatched` in both directions, and the per-model counts summing to `score_coverage["aesthetic"]`. Its autouse fixture stubs both loaders and the scorer module for every test in the file: `POST /quality/score` enqueues onto a process-global job queue, so a job created by one test can be picked up under a later test's event loop and pull a multi-GB CLIP download into a suite that is meant to be torch-free.
