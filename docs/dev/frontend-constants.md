# Frontend constants

This file covers the shared modules under `frontend/src/constants/` that more than one page imports: the caption style table, the DINO layer labels, quality flags, provider presets, gallery sort options, the license vocabulary, media-type checks, terminal job statuses, the detection model registry and the `queryKeys.ts` invalidation helpers. It also holds `utils/apiError.ts`, which is a shared helper rather than a constant. The stores, the `SelectionToolbar` action modals and the JS error console are in `docs/dev/frontend-core.md`; job-completion cache invalidation is in `docs/dev/job-invalidation.md`, and storage keys (`constants/storage.ts`) in `docs/dev/persistence.md`.

## `constants/captionStyles.ts`

`frontend/src/constants/captionStyles.ts` — `STYLE_LABELS: Record<string, string[]>` (style names per model type) and `modelType(model: string): string | null` (maps a model ID to its type key). Shared by `CaptioningPage`, `ImageDetailPage`, and `SelectionToolbar`; do not redeclare locally. Current entries:

| Key | Styles | Notes |
|---|---|---|
| `florence2` | `short`, `detailed`, `tags` | Base Florence-2 (`florence2_large`). `dense` is absent — `<DENSE_REGION_CAPTION>` returns a bounding-box dict, not caption text. |
| `florence2_promptgen` | `short`, `detailed`, `promptgen` | PromptGen v2 (`florence2_promptgen`). `tags` is absent — `<GENERATE_TAGS>` is not supported by this fine-tune. |
| `paligemma2` | `short`, `detailed`, `tags`, `booru` | |
| `joycaption` | `descriptive`, `casual`, `straightforward`, `sd_prompt`, `midjourney`, `danbooru`, `e621`, `rule34`, `booru_like`, `art_critic`, `product`, `social_media` | Shared by both `joycaption_alpha` and `joycaption_beta`. |

Ollama and OpenAI-compat have no entry, so the style picker is hidden for them. `modelType()` checks `model === "florence2_promptgen"` explicitly before the general `startsWith("florence2")` fallback to avoid misclassification. JoyCaption uses `model.startsWith("joycaption")` after the florence2 checks.

## `constants/dinoLabels.ts`

`frontend/src/constants/dinoLabels.ts` — `DINO_LAYER_LABELS: Record<string, string>` mapping layer number (1–12) to a depth word plus a measured property ("Low: scores bunch close together", "Middle: balances look and subject", "Deep: leans toward subject"). Shared by both layer pickers (`QualityPage`, `SelectionToolbar`) and `ImageDetailPage`'s `DinoLayerBreakdown`. **Every label must trace to a measurement**: the old semantic names ("Object parts", "Scene composition") were unmeasured, sat beside a measured default, and one pointed at the wrong end of the stack (M7 Stage 2b, 2026-11-08). The module doc names the source of each band's claim; the measurements are in `docs/dev/quality/style-evaluation.md` § Which layer, and why it moved twice. No label says "default", so moving `DEFAULT_DINO_LAYER` never leaves one stale. Layer 12 keeps "Last block, pre-layernorm" so it cannot be confused with the pickers' separate *Final embedding* option.

## `constants/flags.ts`

`frontend/src/constants/flags.ts` — `FLAG_OPTIONS: readonly [{key, label}]` mapping each quality flag key to its display label. `FlagKey` is the derived union type. Shared by `ExportPage`, `CaptioningPage`, `BulkEditForm`, and `BulkEditPage` — every exclude/skip-flag surface renders this list, so adding a flag here adds it everywhere; do not redeclare locally. The backend counterpart is `ALLOWED_FLAG_KEYS` in `backend/utils.py`, which must be kept in sync by hand.

## `constants/providerPresets.ts`

`frontend/src/constants/providerPresets.ts` — `PROVIDER_PRESETS: Record<string, string[]>` hardcoded model lists keyed by hostname substring (Gemini, Groq, OpenAI, Together.ai). `getPresetsForUrl(baseUrl: string): string[]` parses the URL and returns the matching preset list (or `[]` for unknown/local providers). Used by `ModelPicker` to show a dropdown without requiring a live fetch. Add new cloud provider entries here when preset model lists need updating.

## `constants/galleryOptions.ts`

`frontend/src/constants/galleryOptions.ts` — `SORT_OPTIONS` (`as const` array of `{ label, sort, order }` objects). Shared by `GalleryPage` (sort dropdown and `sortOpt` derivation), `SettingsPage` (gallery defaults sort picker), and `storage.ts` (`getGalleryDefaultSort` bounds-check). Do not redefine the array locally in any of these files. Also `MISSING_LICENSE` (`"__missing__"`) — the gallery license dropdown's sentinel for "no license at either level", which `GalleryPage` translates into `license_missing=true` rather than a `license_filter` entry (see `docs/dev/gallery/filters.md` § Gallery filters), plus the subfolder drag-and-drop id helpers — the `subfolder:` droppable namespace and the `folder-drag:` draggable one, with `canDropFolderOn` (see `docs/dev/gallery/drag-drop.md`).

## `constants/licenses.ts`

`frontend/src/constants/licenses.ts` — mirrors `backend/licenses.py`: `LICENSE_OPTIONS` (id, label, commercial/attribution/share-alike flags, badge classes, display order), `OTHER_PREFIX` (`"other:"`), `OTHER_LICENSES_KEY` (`"__other_licenses__"` — the stats breakdown's collapsed tail bucket, **not** a license id), `FIELD_MAX_LEN` (mirrors the backend column widths so an input can cap before the API 422s), `licenseInfo(value)` (descriptor for any stored value, with an unknown-shaped fallback for `""` and `other:` free text), plus the non-component helpers `isBlankLicense(value)`, `isKnownLicenseValue(value)` (bounds-checks a value restored from localStorage against this build's vocabulary) and `EMPTY_PROVENANCE`. Those live here rather than in a component file because exporting a non-component from one disables fast refresh for it. Consumed by `GalleryPage`, `StatsPage`, `DatasetsPage`, `ExportPage`, `ImportFolderModal`, `hooks/useCustomLicenses`, and the license components (`LicenseBadge`, `LicenseSelect`, `ProvenanceFields`, `ProvenancePanel`, `SetProvenanceModal`); `ImageCard` reaches it only through `LicenseBadge`. The backend is the authority on which ids exist; there is no `GET /licenses/` endpoint (it had no consumers) — the two lists are kept in sync by `backend/tests/test_provenance.py::test_frontend_license_vocabulary_matches_backend`, which parses this file. Never hardcode a license id anywhere else. The matching shared widget is `components/common/LicenseSelect.tsx` (dropdown + the "Other (free text)…" entry, with optional `id`/`ariaLabel` for label pairing and `customOptions` for the "Used in this dataset" optgroup); all three provenance editors render it rather than building their own `<select>` over `LICENSE_OPTIONS` — see `docs/dev/provenance-api.md`.

## `constants/mediaTypes.ts`

`frontend/src/constants/mediaTypes.ts` — `VIDEO_EXTENSIONS`, `MEDIA_ACCEPT` (a file input's `accept`), `hasVideoExtension`, `isMediaFile`, `isMediaDragItem`; consumed by `GalleryPage`'s upload drop handler and its drag overlay. A MIME check alone is not enough client-side: browsers report `File.type` as `""` for `.mkv` and often `.avi`, so filtering on a `video/` prefix drops exactly the files a video user cares about. It mirrors `backend/media_types.py`, which stays the authority (it answers every upload with a `skipped` list) — and unlike `constants/licenses.ts`, **no test enforces the mirror**.

## `constants/jobs.ts`

`frontend/src/constants/jobs.ts` — `TERMINAL_JOB_STATUSES`, the shared `completed`/`failed`/`cancelled` set every "is this job over?" check reads. Imported by `TopBar`, `useVideoExtractJobs` and `ReextractFramesForm`; `store/jobStore.ts` keeps its own copy for the five-minute purge, which is a TTL rather than a UI decision. Three importers is past the threshold for a local copy — a fourth status added to one copy and not another is how they silently disagree. See `docs/dev/job-invalidation.md`.

## `constants/detectionModels.ts`

`frontend/src/constants/detectionModels.ts` — the detection model registry `DetectionRunForm`, `SelectionToolbar` and `ImageDetailPage` pick from (its three importers; `DetectionsPanel` renders existing detections and picks no model), plus `detectionModelFamily`; see `docs/dev/detection.md`.

## `constants/queryKeys.ts`

`frontend/src/constants/queryKeys.ts` — `invalidateProvenanceScope(qc)`, the single list of query keys a provenance write invalidates (`datasets`, `dataset`, `images`, `image`, `dataset-stats`, `export-preview`, `bucket-images`, `licenses-in-use` — the last because a provenance write can introduce a free-text license the pickers must offer immediately; see `hooks/useCustomLicenses`). `["dataset", id]` (used by `Sidebar`, `TopBar`, `GalleryPage`, `CaptioningPage`) is listed separately from `["datasets"]` — TanStack matches by prefix, so the list key does not cover the single-dataset key, and `DatasetOut` carries all four provenance defaults. Provenance resolves at read time, so one write changes several unrelated views at once, and split view means they are often mounted together — every provenance writer calls this instead of listing keys inline. `EditDatasetDialog.renameMutation` (`components/datasets/`, the Edit-dataset modal, which PATCHes the provenance defaults alongside name/description/category), `SelectionToolbar.provenanceMutation` and `ProvenancePanel.save` are its three callers.

The module also exports `DECLARED_CATEGORIES_QUERY_KEY`, the key of the empty-category list behind `/app-data/categories`, shared by `DatasetsPage` and `NewCategoryDialog` (`docs/dev/datasets-page.md`).

The same module's `invalidateDatasetContentScope(qc, datasetId)` is the equivalent list for a write that adds or removes image **rows** — a delete, a rescan, an import, a duplicate resolve. It invalidates `["datasets"]` bare (the list key, which no dataset id narrows) plus nine dataset-scoped keys: `images`, `dataset`, `subfolders`, `dataset-stats`, `tag-stats`, `score-values`, `tag-cooccurrence`, `style-distribution`, `embedding-coverage`. Every one of them is a count or aggregate over the rows that just changed — the last belongs for exactly that reason, a style percentile being an aggregate over the same rows, and costs nothing when nobody is looking because its query is `enabled`-gated on the gallery meter preference. Split view means several are mounted at once, and the global `staleTime` is 30 s — so a writer invalidating only `["images"]` leaves visibly wrong numbers on screen. Its callers are `SelectionToolbar` (delete, move to dataset, style similarity), `ImageDetailPage.deleteMutation`, `GalleryPage`'s rescan completion effect, `TopBar`'s import branch, `DatasetsPage.invalidateDatasetCaches`, `QualityPage.resolveMutation.onSettled`, and the cross-dataset refresh in the four job forms (`docs/dev/frontend-core.md` § Frontend state, the `SelectionToolbar` bullet).

It follows the `invalidateDetectionQueries` convention (see `docs/dev/job-invalidation.md`): the helper carries only the shared set and a caller with extras invalidates them alongside the call — `["videos", id]` on the four paths that can touch a `Video` row, `["licenses-in-use", id]` on import, `removeQueries(["image", id])` on the single-image delete — rather than taking an options bag. The copies had already drifted before extraction: `ImageDetailPage`'s delete was missing `["dataset", id]`, so the sidebar count sat stale after deleting an image from the detail view. `datasetId` is typed `string | undefined` because every call site interpolates a possibly-undefined pane id, and `["images", undefined]` matching nothing is the pre-existing behaviour.

A ninth key rides along, and it is **reset** rather than invalidated: `["gallery-nav", datasetId]`, the detail view's boundary prefetch (`docs/dev/gallery/nav.md`). The difference matters because that entry is not something on screen — it is a *navigation target*, the id list → steps onto. An invalidated entry is still served while it refetches, so a delete would leave → pointing into the pre-delete page for the length of one request and land the user on a row the server no longer has, which 404s. `resetQueries` blanks `data` through a dispatch the mounted observers see, then refetches the active one; `removeQueries` would not do — it destroys the query without dispatching, so a mounted `ImageDetailPage` that does not happen to re-render keeps serving the stale array, which is real in split view where the delete fires from the other pane. It carried `staleTime: 60_000` and nothing in the app touched the key until this was added.

## Shared non-constant helpers (`utils/apiError.ts`)

`frontend/src/utils/apiError.ts` — `apiErrorDetail(err, fallback): string` returns the server's own rejection reason, handling **both** FastAPI `detail` shapes: a plain string (`HTTPException`, 400/409) and an array of Pydantic validation objects (422 — what an over-long `source_url`, or a license that grows past its column after normalization, produces), rendered as `field: msg` joined by `; ` from the last element of each `loc`. Use it in every mutation `onError` instead of a fixed message: a 422 is precisely the case where the server knows which field to shorten and a generic toast throws that away. Its sibling `utils/url.ts::safeExternalUrl` trims and rejects on the *same* character class (`\s` + C0 + DEL + U+0085) rather than calling `String.trim()`, because JS `trim()` and Python `strip()` disagree on U+FEFF/U+0085 and the UI must not render a link the export writes out inert. The module also exports `isNotFound(err)`, the terminal-vs-transient discriminator: a 404 means the thing is gone for good, anything else may be a blip. It is what lets `useVideoExtractJobs`' recovery `.catch` retire a persisted job id on a 404 alone, and what the hand-rolled `retry` short-circuits on `ImageDetailPage`/`VideoDetailPage` read — see `docs/dev/video/extract-ui.md`.
