# Export licensing and provenance manifests

This file covers the licensing half of dataset export: the `license_filter` wire encoding and
its `""` semantics, the Export page's license controls, and the provenance manifests
(`CREDITS.md` / `licenses.csv`) — how they are rendered, why every value in them is escaped as
untrusted input, and the lifecycle rules (partial runs, the numbered chain, supersede).

The export loop itself, the full filter table, and the output options (caption formats,
resize, loss masks, captions-only) are in `docs/dev/export.md`. The license vocabulary and
the dataset→image inheritance these filters resolve against are `docs/dev/provenance.md`;
CLAUDE.md's untrusted-provenance invariant names `_md_inline`/`_md_link`/`_csv_cell` as the
neutralisers this file describes.

## License filters and the Export page controls

`license_filter` is a **JSON-array string** in the preview GET, parsed by `utils.parse_license_filter_param`, for the same reason as the mask labels: an `other:<free text>` id may contain commas. `GET /images/` uses the same helper and the same wire encoding, but **not the same treatment of `""`**: here `""` is a meaningful entry (images with no license recorded), while `GET /images/` expresses unlicensed through its own `license_missing` param and 400s on **any** list containing a blank entry (a mixed `["CC-BY-4.0", ""]` included) rather than silently returning everything. Both agree an empty list (`[]`) means "no filter", never "match nothing". See `docs/dev/provenance.md`.

**Export page license controls** (`ExportPage.tsx`): a **Specific licenses** `<details>` panel holding a "No license recorded" checkbox (which sends `""` inside `license_filter`), the `LICENSE_OPTIONS` vocabulary, and the free-text `other:` rows from `useCustomLicenses(datasetId)` appended below them — a flat checklist, with none of the "Used in this dataset" optgroup that `LicenseSelect` renders. A selection restored from localStorage is bounds-checked with `isKnownLicenseValue`: an id this build no longer knows would otherwise filter the export to zero images with no checkbox visible to explain it. A restored `other:` id that is not currently in use is kept as an extra row (`licenseFilterCustoms`) rather than dropped, so the filter being applied is always visible. All four license states persist under `EXPORT_FILTERS_PREFIX` and are cleared by **"Reset to defaults"** — the page has no button called "Reset filters"; the exclusion breakdown gains a **License** row; the directory-tree preview shows `CREDITS.md`/`licenses.csv` for all three formats; and the completion line's manifest names come from a `["job", activeJobId]` query (`jobsApi.get`) because the SSE progress event carries no `result_data`.

**`unlicensed_count` means two different things.** In the *preview* it is counted over the whole dataset scope, not just what will export — the warning ("you have unlicensed images") stays true regardless of whether the current filters happen to drop them, and the banner's second sentence is driven by the backend's `unlicensed_will_export`, which has already applied *every* filter, so it never claims those images export when they won't. In the finished export job's `result_data` (built in `_run_export_loop` from the accumulated credits rows, surfaced by all three format functions) it counts **exported images only**.

## Provenance manifests

**Provenance manifests**: `_run_export_loop` accumulates one credits row per exported image (using `resolve_provenance(img, ds_defaults)` — the parent dataset is fetched **once** before the loop via `_dataset_defaults`), then `_write_credits(manifest_target, credits)` writes `CREDITS.md` + `licenses.csv` into `manifest_dir` (the `output_dir` root, so all three formats put them beside the concept folder, not inside it). Always written even when nothing carries a license: a missing attribution file reads as "no attribution needed", which is precisely the claim an unlabeled dataset cannot make. `CREDITS.md` groups by license then source, in three tiers (`_render_credits_md._sort_key`): attribution-required licenses first, then the "no license recorded" group, then everything else, alphabetical by license id within each tier. `_EXPORT_COLS` carries the four provenance strings and **no `dataset_id`** — it doesn't need one, because every row in a loop belongs to the `dataset_id` the loop was called with, and that dataset's defaults are already in hand from `_dataset_defaults`. See `docs/dev/provenance.md`.

**Every value in a manifest is untrusted** — scraper, sidecar and EXIF strings. `_md_inline` collapses all whitespace and control characters, escapes the markdown specials that change document structure (`` \ ` * _ [ ] < > # | ``) and bounds the length, so a newline in `attribution` cannot forge a `## <license>` section in a legal attribution document. `_md_link` renders a URL as a link only when `utils.safe_external_url` accepts its scheme; anything else becomes inert escaped text. `_csv_cell` prefixes `'` to cells starting `=`, `+`, `-`, `@`, `\t` or `\r` so a spreadsheet reads them as data — the `csv` module already handles quoting, this is only the leading character.

`CREDITS.md` headings also state every obligation the license carries (`— attribution required, share-alike, no derivatives`, from `LicenseInfo`), and disambiguate an `other:` free-text license so it cannot render a heading visually identical to a curated vocabulary entry.

**Manifest lifecycle**: the export loop is wrapped in `except BaseException` so **any** non-completion — `CancelledError`, a truncated image, ENOSPC, EACCES — still writes the manifests for the partial set before re-raising. Written synchronously (a cancelled task is not obliged to schedule another await) and inside its own `try/except Exception: pass`, so a manifest write that fails on the same full disk cannot mask the original exception. Scoping this to `CancelledError` alone was the original bug: every other failure left images on disk with no `CREDITS.md`, the exact state the feature exists to prevent. The partial file says so in its header ("did not finish" — it covers failures, not just cancels).

Writes go through a temp file + `os.replace`. `_manifest_dest` refuses to clobber a pre-existing manifest describing a *different* file set (identical content is a no-op; differing content lands on `CREDITS.2.md`, `CREDITS.3.md`, … up to `_MANIFEST_MAX_ALTERNATES` (99), after which that last alternate is overwritten) — exports routinely share an output directory, and the manifests live in its common parent. The one exception is **supersede**: `_supersedes_existing_manifest(manifest_dir, dest_dir)` parses the existing `licenses.csv` and returns True when every path in its `file` column is under this run's `dest_dir`, meaning this run describes the same subtree again and should own the canonical name. When the images sit *in* the manifest directory itself (`_manifest_rel` yields `""`/`"."` — a captions-only plain export), every path is trivially "under" `dest_dir` and the prefix test says nothing, so the function falls back to `dest_dir.resolve() == manifest_dir.resolve()`. One decision, read from `licenses.csv`, applied to both files so the supersede state cannot differ between them; anything unreadable, malformed or empty returns False and the numbered chain applies. `_write_credits` returns the names it wrote, which reach `result_data["manifest_files"]` and the Export page's completion line — a supersede, a numbered alternate and an identical-content skip all produce something other than `CREDITS.md`/`licenses.csv`, so the client must not hardcode those two.

A **partial** run takes its own base names, `CREDITS.partial.md` / `licenses.partial.csv` (`_write_credits` picks them from its `partial` flag; `_manifest_dest` alternation then applies within that pair, so two interrupted runs give `CREDITS.partial.md` and `CREDITS.partial.2.md`). Partial runs never supersede. Without the separate name, an interrupted run claimed `CREDITS.md` with its "did not finish" banner and stranded the later *successful* run's manifest on `CREDITS.2.md`, permanently leaving the incomplete one as the file a redistributor opens.

Note the asymmetry between the two files on a *non*-superseding re-export: `_render_credits_md` groups by license and source and names no files, so it is frequently byte-identical across runs and skipped as a no-op, while `licenses.csv` always differs (its `file` column). A `licenses.2.csv` with no `CREDITS.2.md` beside it is that case, not a bug — the existing `CREDITS.md` already describes the new run's credits.

The `file` column is **not** `_csv_cell`-guarded: it is a path this code generated, not scraped input, and the `'` prefix would corrupt a filename starting with `-`/`=`/`@`. The four provenance columns keep the guard. It is **relative to the manifest directory** (`_manifest_rel`), not a basename: images live one level down and a loss mask shares its image's basename. A captions-only run lists the caption sidecar it actually wrote, not the `.png` it never exported. `CREDITS.md` lists every distinct `source_url` in a source group rather than one representative — the primary ingest path records a site-level `source_name` with a per-post `source_url`, so collapsing them drops exactly the citable pages the attribution-required entries need.
